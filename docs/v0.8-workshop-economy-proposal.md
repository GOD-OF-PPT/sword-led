## 为什么继续改玩法

现有 v4 将指数增长的兵器身价全额付成金币；任何未锻裸坯都能换手艺；留剑之外仍每天发三新坯。基线终局金币中位数394,669，三次升级全部买满；无手艺、无升级、不留剑的胜率仍与基线接近。这说明功能存在，尚未形成稳定的成长投入动机。[平衡报告](reviews/T11-4-2-3i6-v4-balance.md:43) [经济数据](reviews/T11-4-2-3i6-v4-balance.md:154)

本提案让同一柄作品真正竞争三个去向：交付/有限变现、换手艺、占一槽带到明天。金币用于已有的备料升级、修印和事件，保守达标仍可完成主线。保持“敲、递、留、启程”，不增加材料管理面板、逐锤换工具、倒计时或隐藏风险。

沿 Game Studio 的 Shared/UI/Foundations 路线继续现有 TypeScript/Vite、Canvas 剑与 DOM 纸单。纯核拥有报价、资格、预算和唯一去向；表现只消费正式 view/Accepted 结果。不上新引擎，不以一张概念图代替实装。

## 付款：身价与真正入袋的金币分开

兵器身价仍按现有三配方、裂损、等级、六格连锻及手艺增值；不把身价直接当成金币。所有报价在处置前显示；钱包跨天保留，收购预算每天重置且不累积。

| 章节/天数 | 当日主委托基础酬劳 P | 当日收购钱袋 B |
| --- | ---: | ---: |
| 第一章，第1–4天 | 100 | 60 |
| 第二章，第5–8天 | 250 | 150 |
| 第三章，第9–12天 | 600 | 300 |

主委托的每条路线 r，以已经真实收下的合格件数 n_r、路线要求数量 k_r 计算：

`累计基础酬劳 F = floor(P × max_r(min(n_r, k_r) / k_r))`

本次基础付款是 `F_after − F_before`。比较比例用整数交叉相乘，最后才向下取整；不是按每条路线分别发一笔钱，也不让调用方声明进度或付款。收件后尚未完成的比例酬劳已经入袋；当天最终仍未达标时照旧失约，不伪造完成，也不追回已经收件的工资。

| 去向 | 本次金币报价 | 是否占用收购钱袋 |
| --- | --- | --- |
| 未完成主委托的合格收件 | 上述基础酬劳增量 | 否 |
| 该合格收件的品质奖金 | `min(floor(max(0, 身价 − 合格路线身价门槛) / 5), 钱袋剩余)` | 是 |
| 普通卖给行会 | `min(floor(身价 / 4), 钱袋剩余)` | 是 |
| 主动回收、断剑返现、收工余剑回收 | `min(floor(该剑原始 base / 4), 钱袋剩余)` | 是 |

同一柄若匹配多条路线，品质奖金采用所有匹配路线中最低的身价门槛；此选择在正式报价中给出。现有替代路线互斥，但实现仍须定义此边界。每次奖金、出售或回收都先读钱袋实际剩余、再同一条正式命令扣减；断剑返现也受此限制，不能通过继承/升级高 base 绕过预算。收工多柄按库存稳定顺序逐柄报价，其总额为剩余预算与各回收额之和的较小值。

第8天第一柄合格轻刃发125基础工资，第二柄再发125。第11天先交一柄合格新剑得300，再改用合格旧剑完成，只再得300；不能获得300+600。已经完成主委托后，余剑即使仍符合纸单也只走普通出售。

**零报价边界：**

- 钱袋用完不阻止未完成主委托收件。第8天合格第一柄仍收下并付125基础工资，品质奖金可以为0。
- 通用最大比例公式若得到0基础增量且奖金也为0，合格收件仍可接受并保留真实去向，不能误套普通出售的零价拒绝。现有十二单的合法新增主进度会取得正基础增量；不为展示0元而新增假委托或伪造当前可达场景。
- 普通出售报价为0时拒绝，剑保留、无 journal/资源变化；明确提示“今日收购钱袋已用完”。不能把拖给来客的不合格剑自动零价卖掉。
- 主动回收可明确零价处理；收工确认逐项说明余剑实际回收额，可能为0。断剑是已经接受的锤击后果，钱袋空时返现为0也照实断裂，不因无法返现撤销损坏。

钱袋只出现在订单/处置实时报价、商人纸单和收工说明中。主画面钱包仍是一个金币数；剑旁用“作品身价”，不再画成必付金币。重要消息靠来客/剑架展示，中央落锤区域保持清楚。

## 三柄行囊：留剑有真正的机会成本

每次开炉共三柄可用兵器：无留剑时三新坯，有留剑时“一柄旧剑＋两新坯”。旧剑仍是原对象、原配方/等级/裂纹/锤势；配方首锤后不可改。余温架仍在每次正式跨天增加15%身价并保留其余状态。余温铁夹的继承仍进入下一天第一柄新坯、上限当日普通底价4倍；有旧剑时仍有第一柄新坯，不把继承偷偷加给旧剑。

当天取下/出售/毁掉旧剑不补发第四柄；下一次开炉才按封炉时是否留剑决定发两柄或三柄。每柄仍只能有一个最终去向。护送捐剑的+20%来料只作用明天实际发出的新坯，有留剑时为两柄；不把旧剑当新来料重复加价。

第8天需要两柄无裂轻刃；第11天保留“旧剑1300或两柄新剑各850”。即使带来不合纸单的旧剑，仍有两柄新坯，数量上可走全部公开路线；没有必须留剑、必须抽某门手艺的硬锁。选择错误会失去第三柄备用坯，不能声称从此保证无风险通关。第12天需重锋，带一柄已锻轻刃不会变成重锋；下一天纸单与“三槽去向”须在接受封炉前说明，允许返回调整，不能到第二天才揭晓成本。

正向例：第4天留400身价作品并选余温架，跨天为 `floor(400×115/100)=460`，直接满足第5天旧剑420路线；没有留剑仍可走新剑630路线。这是公开规则算例，不是某个已回放种子的试玩记录。

反向例：第11天把已锻轻刃带去第12天，它占一槽且不能满足重锋配方；若缺少特别用途，放弃它并得到三柄新重锋，可能比惯性留剑更合理。

## 代码、存档与回滚合同

1. 新增 core-v5/独立正式 SDK，身份 `forge-v5`；新局 schema5，key `sword-led.save.v5` / `sword-led.save.backup.v5`。在批准并完成新版本前，默认仍是v4；新版本上线后保留明确v4继续入口，不能静默开新档覆盖旧行程。
2. v1/v2/v3/v4核心、随机解释器、key、备份、journal原样保留。相同旧journal不能改用新价格回放，也不把v4局内的钱或兵器迁入v5。新旧模式共用已有同源单写锁边界，generation/revision/epoch与导出/重试/内存模式继续。
3. `marketSpent`等日预算只由新核正式命令更新；基础付款由真实进度前后差推出。view给作品身价/本次基础工资/奖金/行会报价/钱袋剩余/明日新旧数量。前端不能提交应付额或完成标志。存档校验完整新journal，恢复/回看不再发一次奖金。
4. 炉谱新增 **schema2**，key `sword-led.collection.v2` / `sword-led.collection.backup.v2`，作品收据带 `forge-v4` 或 `forge-v5`来源；新合法局先经各自正式校验器。旧schema1读取不改写，先预览将导入的解锁/作品、再由用户明确确认导入；确认需绑定所展示的源快照，源变化则重展示，不导入未显示的新对象。导入只并集配方/章节/手艺见闻/挑战与作品，**没有钱包、印记、来料升级或局内兵器**。同源重复导入幂等、不发奖，失败可重试/导出；新局资格冻结，运行中不读取后来改变的炉谱。
5. 作品仍按现有“每单最佳”语义展示并保留来源，不将旧作品伪标成v5。导入v4挑战资格只增加模式选择，不加永久数值。局档与炉谱仍是两次独立写入，不声称原子事务。
6. 回滚用新增revert/旧不可变预览与旧入口。新v5/schema2原件先保留和可导出，再切旧运行版本；不删除用户新旧档、不reset历史、不重编码已认可原画。
