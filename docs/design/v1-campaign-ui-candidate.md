# 完整主线可见界面候选：带着人和炉火走完一条路

正式确认对象现为[完整v1.0合同](../v1.0-lantern-expedition-proposal.md)；本文保留设计探索身份，工具取得时点、回滚与成本等差异以正式合同为准。
2026-10-23。用户已明确主要缺口是“没有完整游戏主线”。本文只提出Game UI前端候选，不是新剧情／关卡／数值合同、实施记录或趣味验收。主线的章数、节点、人物分支与终局条件由后续正式方案定义；这里不擅自固定九关，也不把九次短试锋排成九张表。

## 当前界面为什么只像一段试作

当前[v6标题](../../src/presentation-v6/shell.ts#L5)明确写“雾松关试锋”，承诺是三坯、破木盾、争一件新手艺；[阶段文案](../../src/presentation-v6/copy.ts#L22)主要解释下一锤、三回合和工具练习，尚无长程人物目标。现有[领域状态](../../src/core-v6/model.ts#L39)也没有章节／旅程／人物约定，不能只补一条进度条就宣称主线已经存在。

这不是“主线其实完整，只是被设置藏住”。当前`#x6-save`的“行程”实际服务保存，`#x6-history`在回顾内展示刚才的剑；`#x6-escort`是无姓名、无交互的护送人，文案只说“护送的人在等”。终态按钮又是“再铸一剑”，所以完成一件事后回到试作循环。候选应同时要求真实主线内容和持续可见的叙事承诺；UI只能传达已经成立的事实。

## 一张主屏：同行炉台

玩家幻想保持D「行脚灯炉」：人沿山路移动，带着自己的炉车与剑，替沿途的人解决一件接一件、前后有关的事。不是运营工单，也不是关卡选择器。视角保留手绘近景炉台／道路物件，Canvas画剑和接触，DOM承载文字与明确选择。

整段主线使用同一主屏骨架，只改变所在地、同行人、场景对象和可操作动词：

```text
┌─────────────────────────────────────────────────────────────┐
│ 第X章 · 当前地点                         灯路［展开］   歇一歇 │
│ 替谁完成什么 → 因而能去哪里                                   │
│ 已走地标 ━ 现在的灯 ◇ 下一处地标                              │
│                                                             │
│                                                  当前人物   │
│                    手绘世界／当前目标              一句约定   │
│                                                             │
│              完整剑身 ＋ 自然锤／道路上的实体目标              │
│   三坯／随身物       剑的状态·下一动作后果                     │
│                  ［情境次选］［当前主动作］                    │
└─────────────────────────────────────────────────────────────┘
```

这是构图示意，不是已实现截图。常驻只保一个“当前约定”信息簇和一个小人物提示；路标属于该信息簇，不再另开地图卡、任务卡和人物卡。中央和下中部首先留给剑、锤与实体目标。地图全貌、人物旧话和长规则均主动展开，但**当下目标和主线去向无需打开任何菜单**。

“当前约定”固定回答三件事：`在哪里`、`眼下要替谁做什么`、`完成后会改变什么／去哪里`。例如“渡口｜替阿岚打开护送通道｜让同行人渡河”仅示意文案结构；是否使用这个剧情须由正式主线合同决定。避免主标题只显示“落锤”“争工具”或“第一炉”，也不把说明写成永久三段攻略。

### 手绘场景与两个PC尺寸

| 区域 | 1280×720候选构图 | 1920×1080候选构图 | 保护边界 |
| --- | --- | --- | --- |
| 当前约定 | 左上约280–340px宽，地点小字＋两行目标，短地标带在其下 | 约400px宽，以留白放大层级，不添更多常驻条目 | 不跨屏长横幅；不覆盖中部目标caption。 |
| 炉台主体 | 大剑大致占横向28–74%、纵向48–70%，锤保持原自然比例，接触落在台面 | 主体比例稳定，不把空位填成面板 | 柄与尖完整；风险／动作不压剑；不拉胖Canvas补空。 |
| 当前人物 | 右侧约76–94%，下缘落地，整个人物`contain`；只留姓名与一句当前约定 | 放大人物材质与姿态，仍是一位当前说话者 | 不在人物上覆盖巨纸单，不挡挥锤；未参与本场的人不排成头像墙。 |
| 道路行动 | 人物退到路径一侧，实体木卫／绳／闩等居中偏右；手中剑完整位于下方 | 以景深、距离和人物位置表现前进，不横排多个目标卡 | 保真实目标44px以上命中区；caption与余火分位，不压手中剑。 |
| 随身资源与动作 | 左下短实体挂架；剑下只列当下强度／状态／真实风险；底部最多一主一情境次选 | 字号、间距随尺寸增大，不增加等权按钮 | 主目标不可被商人提示／事件通知挤走；保存异常出口仍清楚可见。 |

主题继续深靛与雾蓝山路、暗木铁器、局部纸墨；炉橙用于制造／回报，玉青用于可通行与已完成，朱砂用于实质危险。纸只出现在信件、交易说明和回顾，不给每个数字铺一张纸。标题用现有楷／宋气质，正文用可读中文系统字体；候选正文16／18px、辅助14／16px，关键动作至少44px。不靠颜色单独区分未到、当前、完成和失约。

## 让人物承诺真正留在主屏

可以复用现有阿岚／阿禾／杜伯三位身份的视觉基础，但是否沿用其v5故事、关系和终局必须明确选定，不能把旧版剧情自动灌入新档。

当前人物不再只是订单肖像：到达时站在路／炉边，先说一句眼下为什么需要这柄剑；行动后根据真实结果换姿态、改去向；离开前说清下一次会在哪里遇见。主屏保这一句未完成的约定，人物名可直接展开旧话与具体要求。比如“信还没过雪线”比“主线进度3/9”更能给当前制作以去向；这仍只是文案形式，不代表已批准该事件。

每章应让同一个人的承诺跨场继续：前一场提出问题，中间实际物件／道路发生变化，后面人物回应玩家用过的剑和做法。只在章节结束弹一封长信，或每站换一个陌生发单人，都不足以形成可见人物线。回应由正式主线事实选择，不能让失败／部分完成都播同一张致谢笑脸。

## surface层级：世界先动，页面再解释

| 层级／surface | 何时出现与内容 | 形态与主要选择 | 与主屏的关系 |
| --- | --- | --- | --- |
| 标题／继续主线 | 初次说明终点承诺；已有档显示当前地点、同行者和未完成约定 | 沿现有山路：左侧标题、两句动机；`启程`或`继续到某地`为主动作。种子／保存技术细节低权重 | 不能仍只承诺“试一次工具”；不能未开发就标“完整主线可玩”。 |
| 当地行动主屏 | 锻造、用剑、当前人物、当前约定和下一地标 | 上述同行炉台；一个实际主动作 | 每站维持认知位置，变化来自世界和行为，而非九套工单表。 |
| 章节／抵达 | 真正进入新地区，或本章条件已结算 | 地景先占主要画幅，章名与一句新处境在留白处；人物出现后进入当地行动 | 不跳过前因直接换章节编号；不在每小目标后强制再看一页教程。 |
| 事件 | 道路中出现具体求助、阻碍或取舍 | 保当前世界，前景一个人／物件，局部纸条写短问题和最多2–3个实质选项；选择前给当下代价／之后影响 | 临时替换当前行动区，明确暂停落锤；不是右上角一个必须从菜单寻找的通知。 |
| 商人 | 正式行程允许并实际到访时 | 人在炉车旁摆摊；一件正在比较的实物为焦点，旁有最多两件可切换。说明与确认只为选中物出现 | 进入独立情境，收起锤击与事件选择；交易后带实物回主屏，不留常驻商城九宫格。 |
| 灯路／旅程总览 | 主屏可直接打开，也可在真实章末引导一次 | 一条有方向的墨线行程，已走地标、当前位置、下一地标及远方终点；点当前／已走地标看人物与作品记忆 | 不是设置的子页，不是可免费跳关的地图；长历史在这层，当前约定在主屏仍常显。 |
| 地区后果／章末 | 本章真实条件结算，完成与未完成有区别 | 同镜头亮／暗／部分变化，人物短回应，再给“继续去下一地标” | 地点与人先回应，再给短事实；不让钱和奖励列表盖满后果场景。 |
| 全局结局 | 主线真正到终点或终止 | 完整地景＋三位相关人物各一句后话＋实际留下的关键剑；事实详情主动展开 | 真终点与中途一炉回顾分开。中途不能总用“再铸一剑”回开头；全局终态才给新旅程与回看选择。 |

章节／事件／商人是不同的叙事节奏，但共享同一视觉材料与返回位置。一次只开一个情境surface，不在商人上叠事件、再叠人物信件。进入时取消未提交输入与表现，关闭后回到原地点／人物／正式进度；阅读本身不能推进章节、扣钱或领取奖励。减弱动效时直接显示真实前后姿态与路线变化，无需走路镜头或漂浮字幕才能理解。

**地图缺口要明确。** 当前D目录没有一张已交付、可用作完整主线地理地图的独立位图。`ending-twelve-lights`确是三人望向完整亮灯道路的俯瞰结局图，但灯已全亮、人物与终态烘焙其中，不应拿它充当早期进度地图再加几个暗点。第一候选可做符号化“路谱”：原生可编辑的短墨线／地点名／灯印，配当前地区缩景，明确只是行程而非可自由探索地理图；若正式主线需要完整手绘地理地图，应列为新资产缺口，另行制作，本轮不假称已有。

同理，现有三主角只有等待／致谢两姿，商人主要是头像；复杂情绪、重要对峙、全身商队缺少对应素材。优先利用切景、人物站位、现有状态图和精炼台词，不能用不断抖动／发光代替剧情表演，也不能让同一笑脸承担所有失败回应。

## 对当前v6界面的最小结构性调整候选

- 标题把试锋演示的局部承诺换成正式主线的起因、终点与人物牵挂；继续按钮直接说明正在继续哪一章／地点。`/v6.html`与默认v5如何交付另有范围约定，本文不切入口。
- `#x6-heading`从纯操作标题分成“常驻当前约定”和短期操作提示；`#x6-purpose`服务当下因果，不承担整章历史。章节、地标、人物名不能由renderer根据锤数猜。
- 将“灯路／旅程”作为独立可发现入口；保存／恢复继续由原保存surface负责，避免同名“行程”混淆故事与文件管理。保存异常仍在主屏可见，不隐入叙事抽屉。
- 保`#x6-forge-scene`和道路物件的场景职责，增减人物与环境由正式主线投影驱动。当前`#x6-escort`只适合路上的护送小人，不等价有名字角色与完整关系线已经做完。
- 把局部试锋回顾与最终结局拆清：一站做完后人物回应并去下一地标；真正终态才展示全局人物后话与关键作品。没有下一段实装时，明确写尚未开放，不画出可点击的虚假大地图。

正式主线view至少需要直接给UI：所在章／地点、当前约定与关联人物、实际可前往的下一站、已发生的世界变化、人物当前回应、事件／商人是否可用、终局类型与实际作品记忆。以上是展示信息责任，不是renderer自建第二套剧情判定，也不在本候选里增加存档字段或奖励协议。

本候选成功与否的界面判断是：不打开设置，玩家是否知道“我在为谁走这条路、现在做什么、下一站为什么值得去、刚才真正改变了什么”。即使这些都能看懂，仍须实际完整主线内容与玩家选择支持可玩性；漂亮路谱、更多人物头像与章节编号不能替代它。
