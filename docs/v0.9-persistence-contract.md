# v0.9短段保存与恢复合同

本段保存独立于v0.8十二天。规则`forge-v6`、schema6、主档`sword-led.save.v6`、备份`sword-led.save.backup.v6`；只有正式纯核全journal重建后逐字段相同的状态才可恢复。旧wallet/资格/剑/炉谱不导入。实现复用已经存在的codec/session/WriterLease机制，不改旧解释器。

- 主备每次都保各自读/解析状态；未来版、损坏与拒读不能当空档。读取不自动修复或清除原文，原始两槽可以导出。
- 新开、恢复备份、放弃当前内存局等影响进度的动作有明确可取消确认。恢复的确认必须指向刚刚展示的原文；原文变化后重新预览，不用旧确认恢复另一份。
- 新v6窗口用独立`writer.v6`锁，同模式只允许一个持久写者；v5原页仍是自己的规则与保存，不占本段的v6锁。不取得锁时明示只读/重试，只有用户明确选择才进入不保存试玩。
- 命令仍须匹配run/revision/generation；Accepted立刻成为当前事实，写失败也保留内存结果，提示尚未存好，可导出或精确重试保存，不能为保存再打一锤/再发工具。
- 暂停、隐藏、离页清除controller未执行的技法标记与动画；已经接受的强度/随机位置/回合/奖品不撤销。页面恢复只重建事实，不补播旧锤或发旧钱。
- 导出当前局保Accepted事实；导出磁盘原文分别标记主/备读取是否成功，读取失败不把null说成空档。未识别版本也可先导出原文再决定。
- 显式不保存模式不写主备，刷新关闭的丢失后果在选择处说明；不把临时状态伪装成正式保存成功。

前端主画面只保一个简短保存状态，详细恢复/原文/重试置于行囊内。它们支持继续玩，不以实现术语/故障清单占据炉台。必要验证围绕当前schema/单写/代际/写失败/旧档保留，实际结果写入执行任务回执；此文档不预填测试或人类认可。
