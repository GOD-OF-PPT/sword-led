# 整局策略模拟合同

T06 / 2026-10-18。模拟版本 `sim-v1`，规则仍为 `forge-v1`。入口为 `scripts/simulate.ts`；模拟不读写玩家存档，不注入资源、随机结果或终局。结论与原始证据见 [R2](reviews/R2-kernel-and-balance.md)。

## 运行与证据

```bash
npm ci --registry=https://registry.npmjs.org/
npm run simulate -- --seeds 1000 --prefix verify-v1 --suite full --workers 6 --out tmp/my-verification
npm run simulate -- --replay docs/evidence/T06/verify-v1.medium-victory.json
npm run simulate -- --replay docs/evidence/T06/verify-v1.raw-defeat.json
```

Node 进程使用项目锁定的 TypeScript 编译到忽略目录 `tmp/simulation`，无需额外运行时依赖。workers 为 1–8 个普通数值计算线程，不是代理；每个线程只处理独立完整局，汇总顺序与线程结束顺序无关。指定 1 可串行复跑。输出名已存在时立即报错，避免覆盖证据。

参数：seeds 为 1–10000 的整数；prefix 为 1–40 位 ASCII 字母/数字/下划线/短横线；suite 为 full/base/abuse，默认 full。默认种子为 `verify-v1-0000` 至 `verify-v1-0999`，每个场景使用相同种子集合。训练检查使用 `train-v1`，与验证集合分开；本次没有根据验证集合调整数值。

输出为统计 JSON、逐局 CSV.gz、中等误差自适应胜利与原坯交货失败 witness。报告记录完整场景配置、来源文件/lock SHA256、规则/模拟版本、Node/平台、时间、行数和 CSV 压缩字节哈希；每局行另存最终状态哈希。witness 保留完整正式 journal 与快照，回放命令先通过 validateRun，再重做策略和输入模拟，比较状态及指标。

## 规则调用与信息边界

每局只用 createRun、applyCommand、getRunView、validateRun 改变或校验规则状态。策略只收玩家可见 RunView 及三种锤法的报价，不接收 RunState、seed、下一次随机数或未来落点。选锤后才抽取该击的输入误差。输入流与 stock/strike 完全分开，取消/查询/重复命令不抽输入样本。同一动作期间的可见报价只计算一次并复用；不跨命令缓存。

每步检查资源账本、三件数量、阶级/热度/应力/完整度、终结不可逆、日志与 revision、双随机流抽样数。普通策略最多 2048 Accepted 动作，必须终止于胜利或失败；卡局、非法策略命令或回放错误均使 CLI 非零退出，不被计为正常失败。每个最终状态都实际运行完整 validateRun 回放，不抽样验证。

## 操作误差假设

游标从左端开始，完整周期为轻/标准/重锤 1600/1400/1200ms。模型尝试在第一次经过中心时松开，即周期的四分之一。每击取 14 个独立输入流样本：失误判定、失误位置、12 个抖动样本。后 12 个 uint16 均匀数减其总均值，组成近似钟形误差；它不是精确正态分布。负的按住时长钳制为 0。固定整数时间单位 1/65536ms，再用三角波四舍五入为 0–10000 落点。

| 模型档位 | 抖动尺度 ms | 随机松开占比 |
| --- | --- | --- |
| low | 110 | 12% |
| medium | 50 | 6% |
| high | 22 | 2% |
| perfect | 0 | 0 |
| blind | 0 | 100% |

失误位置均匀分布于游标第一段往返的前半周期。输入源使用独立的 `sim-input-v1|seed` FNV/Mulberry32 流；只复用纯随机工具算法，不读取业务随机状态。慢速场景把周期乘 1.5，时间误差不缩小，因此改变实际命中分布；正式风险、配额与奖励完全相同。

这些是可比较的建模假设，没有来自真人的校准；low/medium/high 不是已测得的人群分层。报告给出实际精准/普通/偏击数量，而非把档位直接当固定精准率。

`activeInputSeconds` 只累计模拟按住时间 + 每击 450ms 反馈假设，不计阅读、选料、交货、商店、思考、鼠标移动、菜单或休息。它既不是脚本墙钟耗时，也不是整局真人时长。比较工具效率时同时看通关率、每轮时间及**胜利局**时间，避免把提前失败误当快通关。12–20 分钟仍是待网页试玩验证的产品目标。

## 策略与 53 个场景

base 共 36 个：保守/均衡/激进 × 固定轻锤/标准锤/重锤/自适应 × low/medium/high。full 另加均衡四锤法 perfect（4）、自适应 medium/high 的 precision/stability/none 升级（6）、low/medium 慢速（2）与五种滥用/对照，共 53 个。

三种策略均在可见价值达到目标后交货；风险过高、无法击打时保值交货；煤有限，低热且下一击不能直接达到目标时才加热。留作回收的铁件不是交货收益。

- 保守：优先耐久高的铁件，将缺口均摊给全部 active 件，以普通击风险评估；完整度 1 时风险上限 18%，其他 30%。完成订单后不额外加工就回收。
- 均衡：前六轮尽量预留一件供废料，后续均摊缺口；以精准风险评估，风险上限 24%/42%。订单完成后的余料尝试到二阶再回收，风险上限 16%。
- 激进：优先原值高的铁件，目标为均摊缺口的 1.25 倍，前三轮至少四阶、之后至少五阶；风险上限 38%/55%。达标余料尝试四阶再回收，风险上限 16%。

自适应根据可见的精准进度、普通击风险、剩余热度、周期与下一阶完成目标的机会评分。风险权重在最后一格完整度时乘 3；三类策略的时间/风险权重不同。它是固定启发式，不声称最优，不预知本次输入误差或业务抽样。固定锤法不偷偷切换。

heat/precision/stability 是**优先购买顺序**，分别先买风箱/锤柄/砧台，再购买其他允许且买得起的商品；印记 ≤1 时先尝试修补。none 完全不购物。路线不是只能买某一商品的强制流派，也不保证同等花费。

五种对照：原坯直接交货；全部回收；无操作及非法满热加热；盲目重锤、不加热不购买、不能敲时交货；均衡自适应 medium 每个 Accepted 后重发原旧 revision 命令五次。最后一项在 full 中逐种子比较无重发对照的完整状态哈希。

无操作会停留在首轮，既不获利也不自动受罚；游戏按操作轮次推进，没有现实时间订单倒计时。有限集合中的盲击无通关不能证明任意盲击永远无法通关。本地合法 journal 可被人改写，模拟不承担联网反作弊承诺。

## 如何解释结果

规则允许有印记时在最终轮未达标仍通关；不能为了提高表面难度把该胜利改成失败。以之前达标积累的容错换取最后两轮违约是合法决策。原坯、纯回收等无需锻造的路径仍须实测不能免费通关。

轻锤可能更稳，标准/重锤可能节省操作，不能只比较一个胜率。不同策略的低胜率也可能来自启发式保值过早，不能推断该风格所有玩法必输。可复现的中等误差通关只证明存在正式可到达路径；真人可理解性、乐趣、视觉和实际全页面流程仍在 T08–T11 验证。
