# 需求到验收的映射

版本 v0.2 / 2026-10-18 进度更新。下表为验收合同；当前有原始输入、设计/概念/R1、[T04内核](reviews/T04-kernel-validation.md)、[T05商人/存储/窗口生命周期](reviews/T05-persistence-validation.md)与[T06整局模拟/R2](reviews/R2-kernel-and-balance.md)的规则、Adapter、M与浏览器SDK证据。**实际游戏页面与玩家视觉/交互/主观可玩性验收仍待对应任务**。OpenSpec 位于[提案](../openspec/changes/add-forging-game/proposal.md)，F/E/S/U 是稳定能力标识。

证据层级：D 文档核对；K 正式纯内核/存档测试；M 调用正式内核的策略模拟；B 浏览器实际行为；V 实际渲染截图/视觉检查；H 人类选择或试玩反馈。某一层通过不能自动代表其他层通过。

T07已新增[派生美术/设计预览证据](reviews/T07-art-validation.md)，覆盖AC29、资产可拆/alpha和设计层两尺寸；它不是AC25–27/30–39实际游戏消费者与完整玩家流程的验收。实际接线仍按原矩阵完成。

T08阶段的[入口/工坊证据](reviews/T08-workshop-validation.md)覆盖主菜单、教学隔离、S03/S05输入取消、真实操作与两尺寸；当时不以26检查代替整局。T09新增[R3完整界面证据](reviews/R3-full-contract-flow.md)：30页面检查实际覆盖AC12、AC16–17、AC21、AC30、AC32–33和阶段两尺寸，含336动作通关/14动作失败、四商品、修补与限购、收据/终局、刷新与重开。它不代替AC36–39完整品质、AC41真人评价及T11–T12最终验收。

T10已加入[品质接线与验证](reviews/T10-quality-validation.md)，覆盖AC22–24的玩家恢复出口、AC27受控回调节奏和真实JS回调预算、AC36完整纯键盘胜负/商人/焦点、AC37独立设置与系统动效、AC38原生音频图/静音/拒绝/旧恢复取消，以及AC39空闲rAF与旧消费者回归。硬件高刷/GPU/全浏览器/真人听感仍不由这些结果代表，T11–T12保持原范围。

## 测试执行要求

T05 提供后台与存储 SDK 的证据；跨层场景中的可见页面/提示和真正游戏消费者接线必须在 T09–T11 闭环，不能把 SDK 测试夹具当玩家界面验收。

核心测试覆盖正式 Interface 的可观察结果、不变性和异常路径，不能只断言私有函数回传其输入。固定种子要有已知回放向量，同时给真实 RNG 跑分布/整局；不只把所有随机值替换成成功。

浏览器按生产构建预览执行，记录浏览器与版本、视口、规则版本、种子、步骤、结果、截图与失败 trace。允许可控时钟稳定时机输入；不跳过商人/日终、不直接把存档改成胜利。版本化存档的异常场景可使用专门损坏样本，但不能把其结果冒充正常完整局。

性能报告记录实际环境和预算偏差。视觉检查同时查看两个目标尺寸、动态状态与减弱动效，不能只截一张静止主界面。

所有完成记录须区分“已运行通过”“已运行失败并修复复验”“工具/反馈缺失未验证”。T02 建立矩阵不代表其中任何业务验收已经通过。
