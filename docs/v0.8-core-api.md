# v0.8 经营内核

已批准的经营规则现由 `src/core-v5` 和构建产物 `dist/sword-led-v5.js` 实际执行。SDK 已接 schema5 局档、schema2 带来源炉谱与显式旧炉谱导入，详见[保存合同](v0.8-persistence-contract.md)。当前网页仍用 v4，下一步接第一章页面。

`npm run build` 会追加独立 v5 SDK 构建，原网页和八个旧 SDK/共享块继续原字节。完整构建输出应一起保留。

```js
import * as forge from './dist/sword-led-v5.js';

const created = forge.createRun({runId: 'my-workshop', seed: 'a-road'});
if (!created.ok) throw Error(created.error);
const opened = forge.applyCommand(created.state, {
  runId: created.state.runId,
  expectedRevision: created.state.revision,
  action: {type: 'continue'},
});
if (!opened.ok) throw Error(opened.error);
const view = forge.getRunView(opened.state);
// view.blades[0].quote.amount 是本次实际收入，blade.value 是作品身价。
```

| 正式接口/字段 | 使用方式 |
| --- | --- |
| `deliveryQuote(state, blade)` / `view.blades[].quote` | `matched`、匹配路线、最低品质门槛、`baseFeeDelta`、`qualityBonus`、`saleQuote`、`amount`、`marketCost`、`allowed/error`；按钮读取报价，不由页面重算工资 |
| `view.market` | 当章基础工资/钱袋、已花预算、剩余预算、已付基础工资；钱包仍是 `view.coins` |
| `recoveryQuote` / `view.blades[].recovery` | 受剩余钱袋限制的原 base/4 返现，主动回收与断剑、收工共袋 |
| `view.settlement.recoveries` | 按库存稳定顺序逐柄扣预算后的实际回收额；不能将每柄单独报价直接相加 |
| `view.blades[].barter` | 当前兵器是否可献给商人，包含等级至少3；商人/货物资格仍另核验 |
| `view.next` | 留剑、两或三新坯、总三槽、次日配方/旧剑条件匹配、第一新坯继承额 |
| `Delivered`、`Hit`、`Disposed` | Accepted 结果的实际工资/奖金/返现及钱袋剩余；动效只读，取消动效不撤收入 |
| `validateRun` | 从 v5 初始身份重放全部 Accepted journal，再比较整个快照；不能迁入 v4 余额或兵器 |

普通零价出售返回 `market_exhausted`，状态及 journal 原样返回；合格主单即使钱袋空仍可收件。主动零价回收必须由显式命令决定，不能把拖交不合格剑自动变成出售。换手艺等级不足返回 `blade_unworked`，不是“必须锤三次”。

正式轨迹 `v5-economy-0` 完成十二单，包含第八天125+125、第十一天先新后旧300+300和三次备料升级；这是单一合法可达性记录，不是胜率或趣味证明。另有真实第五天旧剑交付、三种结局、八项定向经济检查与完整回放，范围和原始数据见 [R3.22](reviews/R3-22-workshop-economy-core.md)。
