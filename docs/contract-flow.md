# 经营、收据与终局接线

T09 / v0.2 / forge-v1。沿用已确认的十二轮、三件来料、三次商人和印记惩罚；没有修改规则数值或存档schema。

## 玩家流程

交货确认显示本件价值、交货后的订单与金币；回收确认显示废料和放弃的交货估值。提前收工显示剩余件数、合计废料、缺口、印记前后数，最后一枚时明确说明契约会终止。取消不发命令。

三件处理完仍等待结算。日终纸面收据展示实际交货/配额、印记变化、三件材料/阶级/去向、交货收入、回收/破碎废料与损失估值。收据读取已完成记录，不重新领钱、回收或扣印记。

第3/6/9轮存活后的日终继续进入商人，终局没有商人出口。四商品展示等级、效果、两种价格、本次已购/满级/印记完整/余额不足原因。购买确认包括扣费后钱包；修补额外显示印记变化。离开确认说明下一轮及下一次商人，取消保留本次购物机会。煤与三件来料只在正式leaveMerchant/advanceSummary成功后配给。

通关与失败分别使用完成/终止印章和纸质契约印记，展示达标/违约、余额、最高阶、破碎件数和损失估值、累计收入/支出；可展开逐轮交货/配额/印记账本及全部购买记录。第12轮违约后仍有印记也会完成契约期，统计保留这次违约。终局可返回菜单、同种子再战或新种子；取消重开留在原总结，确认后重置runId、资源、升级、历史与随机流。

## 模块与动作身份

`core/index.ts`新增只读`getRunLedger(RunView)`，返回已结算轮的收据、破碎估值、最高阶名称与购买标签；复用内部同一材料/阶级/价值表并深冻结结果。它不分配铁坯、改状态、写盘或抽样。`RunView.history`仍是已结算轮，当前工坊未结算的三件不会被重复计账。存档与规则版本不变，旧合法档继续使用。

`presentation/phases.ts`只构造DOM和意图，不导入内核私有公式。`app.ts`为阶段动作捕获当前Ticket，弹窗与按钮不能复用旧runId/revision/generation/路线身份。阶段缓存还包括应用epoch：从菜单继续或暂停回来会重绑当前身份，避免视觉按钮仍在但闭包票据过期。

阶段切换聚焦标题；取消弹窗归还触发按钮；购买后的原按钮若已禁用，聚焦商人标题。长按Enter不穿透到新阶段。菜单、刷新和重读只呈现已保存状态，不重播旧领域事件。阶段页脚持续显示真实保存/只读/不保存状态，重试保存后也刷新。

## B风格与尺寸

使用既有空工坊背景、透明商人器具、纸色/墨线/青色达标/红色违约及纸质“契”牌。商品与统计均为真实DOM，不使用带假按钮的整张设计板。日终三张来料收据对应三次机会；终局长账本放在可展开区域，底部主要出口固定可见。

1280×720的商品卡将等级/名称和价格/购买分别并排，四商品与底部出口同时可见；1920×1080保持较疏的手账排版。文字最低12px，对比度按实际计算样式核查；耗尽印记仍有文字和虚线，不依赖颜色。超长账本在内容区滚动，不能遮住重开/返回。

## 验证与回滚

生产页面以原生键盘事件和受控时钟重放已存在的胜利策略输入；允许毫秒量化后在同一时机等级内微调按住时间，不直接调用页面内核或注入资源/终局。每个动作检查revision，最终对照整个规则状态和随机流，保留实际journal。另一局独立走到第三轮失败。购买、刷新、菜单继续、取消与重开均通过DOM执行。

同一轮还用已验证的102动作样例从第一轮实际走到第六轮，检查锤柄、修补、两币不足、当访限购及下一轮效果。规则收据单测核对累计账目和不变性；R3联合美术288姿态、T08输入和存储SDK/真实BFCache回归。证据及实际结果见[R3报告](reviews/R3-full-contract-flow.md)。

回滚使用revert提交并重新构建；不清空主档/备份、不改原始输入或B素材。T10仍负责声音、独立设置保存和完整异常体验；T11–T12负责更广浏览器/性能/真人反馈与最大交付审查。
