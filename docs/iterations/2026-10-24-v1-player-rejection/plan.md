# v1.0实际否定后的调查与优化

用户仍认为玩法不完整且动效有缺陷。既有九站/三结局可达不等于玩家体验完整，不能用上轮通关与检查反驳本次反馈。按明确调用的Game Studio转入game-playtest、game-ui-frontend与foundations，保现有TS/Vite纯核与DOM/Canvas；不盲迁引擎。优先交互、画面、流程的实际改进，兼容和大矩阵最低。

顺序：T1同一任务内并行：实际当前默认版本新手操作与逐帧捕图、源码全动作事件/表现映射调查、live相关官方玩法/玩家原评检索。形成具体可复现缺陷和玩法完整性缺口，不只给建议；T2集中修复已批准玩法内的动作表现、输入和阶段引导/反馈及遗漏接线；T3全面有界PC实图/操作复核并修缮，原预览冻结更新、提交推送、真实回执。

如新证据要求改变已批核心计价/主线/供给/存档合同，先落地现有范围内修复，再形成具体可审阅差异，并仅在适用OpenSpec明确要求时针对该新合同请求批准；不能因为泛改进就反复要求全盘确认。当前完整v1已具体获批、修复与交互细节无需再次确认。

风险：更多剧情文字冒充玩法、只修测试看到的边缘帧、叠特效遮操作、旧结局存档损坏、改规则来掩盖无效操作。核对当前实体互动、输入→预备→接触→对象回应→结果→下一步，普通/技法/敌方压力/援手/移交/关卡切换/结局各有清楚因果。既有规则与正式view为唯一authority；Accepted立即存，表现取消不回滚。

验证：只复现和验证本轮相关真实问题，实际现代PC输入与关键截图/短序列，必要类型/构建及受影响规则，不重跑历史兼容/种子矩阵。不把脚本选择最优解当真人乐趣、截图精美或全部游戏完整性验收。保存原源、原负评、旧不可变预览；回滚新增revert/旧预览，不清档或覆盖素材原件。
