# v0.8 独立行程与带来源炉谱

`dist/sword-led-v5.js` 已导出正式保存会话。当前默认网页已接 v0.8 第一章，原十二灯页面在 /v4.html；新页面使用实际报价与独立存档，详见首章指南。

| 内容 | 主槽 / 备份 | 封装身份 |
| --- | --- | --- |
| 新行程 | `sword-led.save.v5` / `sword-led.save.backup.v5` | schema5 / `forge-v5`，完整 Accepted journal 回放 |
| 新炉谱 | `sword-led.collection.v2` / `sword-led.collection.backup.v2` | schema2 / `forge-collection-v2` |
| 旧炉谱导入来源 | `sword-led.collection.v1` / `sword-led.collection.backup.v1` | 只读旧 schema1，由旧校验器解释 |

`createV5BrowserSession()` 继续使用同源 `sword-led.writer` Web Lock。新旧行程互不覆盖；同源另一版本写入时，新会话进入只读。非浏览器场景可传 `createV5SaveRepository`、原 WriterLease、新 `createCollectionRepository` 及可选只读 `createLegacyCollectionSource` 给 `createV5Session`。

`startNewGame/resume/dispatch/retrySave/recoverBackup/useMemory`、两类订阅、暂停/释放等继续采用既有 generation/expectedRevision 合同。Accepted 后保存失败仍保留准确内存局；局档保存成功但炉谱失败时，两者分别报告，不能称为原子事务。`getCollectionSnapshot()` 给出 data/pending/problem/lastSave；`retryCollection(generation)` 只同步已接受成果，不发新命令或金币；两个 export 方法不写盘。未知/损坏原件保持，备份恢复需要明确确认。

作品收据新增 `rulesVersion: 'forge-v4' | 'forge-v5'`。`collectionFromRun` 先选择该版本正式校验器完整回放；炉谱自身校验有界收件字段和公开路线，不声称每张作品保存了整局 journal。并集保留解锁和每单最高作品，同分用 canonical JSON 稳定选择；旧作品不会改标成新规则。炉谱不含钱包、印记、升级、当前手艺装备或局内兵器。

## 旧炉谱的预览与确认

1. 调 `previewLegacyImport('main')`（或明确选择 `'backup'`）。返回的 `preview` 有 id/generation/source/savedAt、将导入的 collection 和并集后的 merged；此操作不写任何槽、不改当前资格。
2. UI 展示该快照的来源、解锁和作品，再将 `preview.id` 传给 `importLegacyCollection({generation, confirmed:true, previewId})`。不能提交客户端生成的作品或奖励。
3. 会话只使用私有保存的那份收据，检查来源原始字节和当前 runId/revision/generation。源已变、票据已消费、取消或上下文已变，返回 `legacy_changed`，须重新预览；不会悄悄换成新源或备份。
4. 关闭窗口/取消用 `cancelLegacyImport()` 清票据。浏览器旧槽变更事件也只清未消费预览；不会自动导入。只读或内存模式可查看来源，但不能持久导入。
5. 确认后的写盘失败保留已确认的内存并集，可重试/导出。之后旧来源即使新增成就，重试也不会把未展示的新内容带入。重新预览相同来源再次确认是幂等的。

当前局的 `initialEligibility` 冻结。只有新建局从已持久的新炉谱读取资格，未保存/未确认成果不能提前解锁；新局仍从零金币、零来料升级和未装备手艺开始，照常发本局三柄新坯。新旧原件和旧入口保留，回滚不删除新槽。

必要检查与局限见 [3l.2 实施记录](reviews/T11-4-2-3l2-persistence.md)。首章已将 source 标签与预览/确认接为实际页面，后续扩展中后段经营。
