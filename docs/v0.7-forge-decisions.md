# 炉前决策投影

3j 的四个只读入口在 `src/presentation-v4/decisions.ts`。输入只收 `ForgeView = ReturnType<typeof getRunView>`，不收 RunState、session、随机流或操作接口。调用不会发命令或预测下一次随机结果；布局与确认由 app 控制。

| 入口 | 玩家看到什么 | 主要返回字段 |
| --- | --- | --- |
| `forgeDecisions(view, selectedId)` | 当前还差什么、能否现在交、下一锤是否安全连锻；剑离砧/没剑时怎样继续 | `headline/copy/tone`、`action/actionLabel/pieceId`、`missing`、`ordinaryToBurst` |
| `nextDayPlan(view)` | 真正的明日委托及每条旧/新路线、已挂剑的真实次日身价与用途；不要求每炉都留剑 | `day/title/customer`、`routes`、`reserve`、`candidateIds`及短提示 |
| `traitPurpose(traitId, view)` | 手艺对当前/下一目标的用途、与已装备三槽的取舍；赦约已使用时不误售新次数 | `headline/copy/tone`、`costCopy/equipped/replacementRequired` |
| `upgradePlan(view)` | 真实金币报价、可买时明日普通新坯底价变化；手上已有剑不涨价 | `price/canBuy/currentBase/afterBase/balanceAfter`及短提示 |

`tone` 为 `neutral/ready/safe/risk/danger`，用文字表达事实，颜色只是辅助。`action` 为 `deliver/strike/retrieve/select/recipe/plan/settle/none`，只是界面意图，不是可直接 dispatch 的 core action，也不代替当前身份/可写性/按钮启用检查。

`ordinaryToBurst=0` 表示下一次有效落锤是安全连锻；大于零是剑若撑住还需几记普通锤，不能当作保证活到连锻或保证涨价。连锻内部最多几锤与“完成几次连锻”分开；接近身价/等级上限可能提前停止，因此文案使用“最多”。

明日留剑只用公开 `next.reserve` 与同ID的公开剑属性核路线。余温架的实际预览价来自 core，裂纹/锤势保持；一柄匹配两柄委托时仍显示还缺另一柄。没有挂剑时 `candidateIds` 只列以当前身价已经符合明日一柄条件的剑，不虚加尚未承诺的余温。`day=null` 表示最后一日或本局已结束，没有可继续的明日纸单。

升级只在公开 `merchant.canUpgrade` 为真时算可购买的下一档：公开章节底价、upgradeCount和已披露的下一批 supplyPct足够重建同一取整结果。不可买时 view 不区分已买过/记录限制等原因，返回 `afterBase=null`，不虚构一笔还能成交的升级。无商人则 `price=null`。商人具体交出哪柄与其身价由 app 的当前选剑和确认显示。

公开算例：起炉40身价的剑提示“还差60身价”，合格148的剑提示“现在交给阿岚”；蓄满六格显示“下一锤是安全连锻”。第3天可买备料时，公开40→60与180金币对应；已挂536的剑若没有余温架，明日仍是536，不写成自动升值。旧剑420/新剑630、旧剑1300/两柄新剑各850均显示为各自真实路线，不硬劝玩家留剑。

这让已有选择更清楚、贴近操作位置。3i.6 记录的金币富余、成长/留剑对胜率作用弱并没有被文案改变，不能据此宣布经济激励已经修好。浏览器中的最终摆放和实际手感由3j必要试玩核对。
