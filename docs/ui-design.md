# 界面流程与三套风格设计约定

版本 v0.1 / 2026-10-17。状态：信息结构已拟定，三套图稿待 T03 生成；**尚未选定美术风格**。

## 1. 画面服务的核心决定

玩家始终要回答四件事：今天还差多少、这一件值多少、下一锤会怎样、现在收手会得到什么。因此配额/印记、当前价值、裂损/破碎风险和交货/回收行为必须同时可见；装饰不能遮挡它们。

目标为桌面 16:9，基准 1920×1080，同时完整适配 1280×720。不是手机界面放大，不为低版本浏览器加入旧布局。较窄窗口可缩放布局/允许合理滚动，但两种目标尺寸内不需横向滚动，不把主操作藏在屏外。

## 2. 工坊主界面分区

| 区域 | 主要内容 | 信息优先级与交互 |
| --- | --- | --- |
| 顶部订单栏 | 轮次 n/12、已交货/配额、缺口、契约印记、金币/废料、暂停/静音 | 当轮实际交货与印记最高；金币不能伪装为配额 |
| 中央工坊 | 锤、砧、选中铁件、炉火/环境、接触点 | 画面视觉中心；落锤对应铁件，不是点击随机位置收获奖励 |
| 邻近材料信息 | 材料/阶级、当前与下一阶价值、进度、完整度、热度、应力 | 必须说明已经锁定的价值与继续加工的风险 |
| 时机与风险区 | 游标、精准/普通/偏击区、当前锤法热耗与收益、三种对应裂损概率、本次破碎概率 | 游标只在蓄锤时动；风险区域不随跳动重排布局 |
| 三件来料托盘 | 槽 1–3，材料、阶级/价值、active/已交货/已回收/已破碎 | 可点击切换 active 件；终结件保持可查看但不可再加工 |
| 动作区 | 三锤法、按住蓄锤区、加热（煤数）、交货（价值）、回收（废料数）、收工/结算 | 破坏性操作与主击打区留间距；禁用说明原因 |
| 反馈层 | +进度/升阶、裂损 −1、破碎/+废料、已保存/保存失败 | 不覆盖按钮，不抢键盘焦点；本次结果与历史状态分开 |

第一眼应先看见砧上热铁和今天的订单；三件来料是机会数量，不让主界面像背包管理表。所有可操作控件使用真实 DOM，即使外观上融入工坊木牌/金属牌。

## 3. 三套候选共用的示例状态

T03 的三张图都使用下列**同一状态**，不能更换数据让某个方案显得更清楚。这是图稿展示样例，不会被写成正式游戏初始存档。

| 项目 | 示例 |
| --- | --- |
| 游戏名 | 锤下求生 |
| 轮次 | 第 6 / 12 轮 |
| 订单 | 已交货 144 / 290，尚差 146 |
| 契约 | 2 / 3 枚印记 |
| 钱包 | 240 金币，6 废料，1 煤 |
| 选中件 | 2 号精钢，阶级 3「成刃」，进度 9 / 下一阶 14 |
| 价值 | 当前交货 83，下一阶 123 |
| 状态 | 完整度 1 / 3，热度 40 / 100，应力 47 / 100 |
| 锤法 | 标准锤：成功 +2，精准成功 +3，热耗 12 |
| 升级 | 锤柄 1、风箱 0、砧台 1 |
| 风险 | 精准裂损 14%、普通 20%、偏击 32%；因只剩一格，破碎概率等于裂损概率 |
| 托盘 | 1 号熟铁：上品，已交货 144；2 号精钢：成刃，加工中 83；3 号陨铁：粗坯，未加工 28 |

样例可由三次精准标准锤成功、两次普通/偏击裂损组成：精钢进度 9、热耗 60、应力 `5×7+2×6=47`、完整度从 3 到 1。当前精准风险 `6+3×3+2-6+0+floor(47/20)×3-1×3=14%`。三图不必展示每个推导，但不能画出与该状态冲突的数值。

图中文字优先保证“轮次、配额、价值、风险、交货、回收”清楚；细小文字若生成错误，检查时如实记录并针对性修图，不把错误当确定文案。正式产品全部使用可编辑文本。

## 4. 三套风格的实质差异

| 方向 | 空间与材质 | UI 与字体方向 | 适配的体验 | 重点检查 |
| --- | --- | --- | --- | --- |
| A 余烬工坊 | 近距离砧台、深色石墙、炭火、磨损铁与黄铜，绘画质感 | 深色金属/皮革薄面板、温暖纸白字，衬线标题配清晰无衬线正文 | 紧张的手作锻造，敲击触感强 | 暗部仍可读、火焰不盖热铁、不是满屏厚重边框 |
| B 行会手账 | 较明亮的手绘工坊、暖木与纸张、简化可辨的器具轮廓 | 订单纸签/手账标记，较轻松的排版，正文保持清晰 | 有温度的经营与规划，长时间阅读舒适 | 不是菜单/插画封面；风险和破损仍有分量 |
| C 冷铁控制台 | 简洁几何的铁作台、冷灰空间、明确橙色热区，克制的材质 | 细线框、清晰网格、紧凑读数与大面积留白 | 精准、利落的操作与风险管理 | 仍是一间锻造工坊；不画科幻飞船/金融仪表盘 |

色板方向：A 炭黑/炉橙/黄铜，B 奶油纸/暖木/深褐，C 石板灰/冷白/热橙。具体色值、字体及资源规格由选图后的 T07 冻结，不把当前方向当已选 token。

三个方向都生成**实际游戏中的工坊 HUD**，不生成网页着陆页、启动页、手机样机、三联拼图或只有氛围没有控件的概念插画。视角允许各自表达，但锤、砧、铁件、三来料、配额和风险必须可辨。

## 5. 完整页面与浮层

| 页面/浮层 | 进入条件 | 关键内容与出口 |
| --- | --- | --- |
| 加载/错误 | 启动或资源重试 | 资源加载状态、失败项与重试；不删除存档 |
| 主菜单 | 初次进入或返回 | 新游戏、继续、教学、设置；继续显示轮次与存档时间，损坏档给明确说明 |
| 新局确认 | 有进行中存档而选新局 | 将覆盖哪一局、种子输入、确认/取消；取消完全保留旧局 |
| 独立教学 | 首局或菜单主动进入 | 明确“练习，不计入正式资源”；练精准、裂痕、交货与回收；随时跳过/返回；重看教程不替换正在进行的存档 |
| 开轮介绍 | 新一轮开始 | 三件材料来源、配额、印记与煤配给；不阻挡老玩家快速进入工坊 |
| 工坊 | workshop | 本文分区及键鼠行为；三件都终结后突出结算 |
| 交货确认 | 点交货 | 该件当前值、计入订单后的总额、不可继续加工；确认/取消 |
| 回收确认 | 点回收 | 得到废料数、失去的交货价值、回收不计订单；确认/取消 |
| 提前收工确认 | 尚有 active 件 | 剩余件按原样回收、交货缺口、是否扣印记；确认/取消 |
| 日终 | 成功结算且本局未结束 | 当轮订单、三件去向、货币收入/废料、印记变化，继续/暂停菜单 |
| 商人 | 3/6/9 轮存活后的日终继续 | 四种商品、等级/价格/生效时间、钱包、限购/不足原因、确认离开 |
| 通关/失败总结 | 核心进入终局 | 原因、达标/违约轮数、最高阶、破碎损失、购买记录；同种子再战/新种子/主菜单 |
| 暂停/设置 | Esc 或暂停按钮 | 继续、静音/音量、减弱动效、慢速游标、查看操作、返回主菜单 |
| 存档/窗口问题 | 写盘失败、版本不兼容、另一写窗口 | 明确目前是否可保存；重试/备份恢复/内存试玩/返回，不静默重置 |

多个确认框不能同时存在。浮层出现先取消蓄锤并阻断工坊快捷键；关闭回到触发按钮。返回主菜单保留已经接受的动作和已存档状态，不能回退一次破碎。

## 6. 操作与可访问性

- 鼠标：点击三件托盘或锤法；在专用大击打区按住/松开；其余为标准按钮。锤击不能覆盖交货按钮的点击区域。
- 键盘：Tab/Shift+Tab 遍历、Enter 操作按钮；工坊击打区获得焦点后 Space 蓄锤/松开。数字 1/2/3 在工坊且未聚焦输入控件时选来料；Q/W/E 选三种锤法；Esc 取消准备或打开/关闭暂停。弹窗中不穿透触发这些快捷键。
- 可见焦点、真实 disabled/aria-disabled 与禁用说明；弹窗聚焦标题或首个安全控件，Tab 不逃逸到背景。
- 完整度同时有格数/裂纹与数字；热度与风险有文字标签，不能只靠红绿。重要交互目标至少 40×40 CSS px，正文基准 16px、辅助文本不小于 12px。
- 普通文字对比度目标 4.5:1、大字 3:1；主操作与数值在两种目标尺寸都检查。风格图不等于实际对比度测试。
- 系统减弱动效优先生效，关闭震屏/剧烈闪光/密集火星；仍保留文字结果。慢速游标仅改变时间尺度，不降低收益。听不到声音也能知道成功、裂损和报废。

## 7. 选定后派生的设计稿与素材

| 资产/设计稿 | 必要状态 | 拆分要求 |
| --- | --- | --- |
| 工坊背景 | 正常、可压暗的暂停/结算环境 | 无 HUD/文字，无不可移除的活动锤或铁件 |
| 铁锤与砧台 | 轻/标准/重锤姿态，基础/升级表现 | 锤与砧分层、透明 alpha，锤柄完整，接触点/锚点明确 |
| 铁件 | 熟铁/精钢/陨铁，阶级 0–7 的形态语言 | 与阶级/热度/裂纹分开控制；可用形态关键帧+代码状态叠加覆盖全部阶级 |
| 裂损与破碎 | 各完整度、临界、破碎 | 纹理/裂纹层与碎片，不把固定状态烘焙到唯一铁件图 |
| 商人 | 同一工坊中的来访展示、商品与买后状态 | 非必要时不强加人物故事；商品仍是 DOM 可读文本 |
| 日终/终局 | 达标、违约、通关、失败 | 风格一致，数字与统计可编辑，按钮/焦点独立 |
| 交互与反馈 | 精准/普通/偏击、成功/裂损、加热、交货/回收 | 先给状态设计板，再在代码中还原；颜色之外有形状与标签 |

图片输出使用内置 imagegen；需要透明的请求明确 transparent_background=true，并检查 alpha。运行素材放项目目录后才能引用；概念原图、衍生稿和提示词也保留。最终不得靠一张带假按钮的大背景冒充可交互页面。

## 8. 图稿评审顺序

先检查规则信息是否齐全且一致，再看工坊/器具的可辨识度，然后看视觉层次与触感，最后看 1280×720 可读性和可拆分性。每套逐图记录优点、实际缺陷和衍生代价，再请用户选择；不把主观推荐当用户确认。
