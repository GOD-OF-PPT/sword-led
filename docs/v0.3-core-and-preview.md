# v0.3 核心与玩法试玩

> 后续界面：T11.3已接入[D正式资产/全流程与练习](v0.3-d-interface.md)，下文保留T11.2当时的验证范围，不把旧证据改写为新版美术验收。

本阶段对应T11.2，依据[已批准提案](v0.3-gameplay-proposal.md)。正式入口`/v2.html`与原版`/`分别保留。建议先玩前三轮和首个商人；内核已包含十二轮，当前界面也允许继续，不把前三轮或原生几何画面当作最终游戏/最终D美术交付。D「行脚灯炉」的栅格资产与界面精修仍在T11.3。

## 实际可玩的选择

1. 开炉后免费选巡锋齿、桥脊扣或回火砂，再接受一张委托或明确拒绝。
2. 在三件来料中选择剑，点选五节的刃/脊落点。按住/松开鼠标或空格锤击；方向键选点，Q/W/E换锤，1/2/3换坯。改变目标、暂停、失焦或改变慢速会取消未释放的锤，不扣资源。
3. 相邻三个不同落点形成巡锋/守脊/游衡，重复、跳点、偏击和回火会断开临时线。每种纹每把奖励一次，成品轮廓/纹/裂痕由真实已加工量绘制。
4. 看三种时机将造成的热耗/应力/完整损失，再决定继续还是水/油淬火。原坯交价与两种淬火后的成交预估分别显示；预估调用正式定价/委托函数，尚未变成金币或订单进度。
5. 淬火后可反复试剑：切绳、挡击和绕铃各自呈现真实性能档位。试剑、作品簿、选点和设置不写锻造journal，不推进随机或发第二次奖励。
6. 交货保住收益，回收取得废料。收工前列出三件去向、缺口和印记后果；第三轮后到商人处选择新技法，满三槽必须明确选一门换下。

这是规则与操作的试玩入口，仍需真人判断是否新颖、是否重复。初始按键、视图字号和图形不是最终D视觉验收。

## 一个权威内核，两种存档解释器

| 责任 | 实际模块/契约 |
| --- | --- |
| v2规则、命令、预览、回放 | [core-v2](../src/core-v2/index.ts)，`createRun/applyCommand/getRunView/previewStrike/previewQuench/validateRun` |
| 价格/委托/技法/条件数据 | [rules.ts](../src/core-v2/rules.ts)；接受命令和界面预估调用同一正式函数，不复制数值公式 |
| 作品簿/试剑 | `getCollection/getTrial`只读；唯一pieceId绑定快照和去向，最多36件，不取回再售 |
| 会话保护 | [createAdaptedSession](../src/application/persistent-session.ts)复用generation/activationEpoch、dirty、冲突/备份/恢复、不保存、单写租约；默认适配仍是v1 |
| 存储保护 | [createAdaptedSaveRepository](../src/platform/storage.ts)复用主/备份写入、原始token比较和错误状态，codec决定schema/key/规则校验 |
| v2浏览器接线 | [v2-persistence](../src/application/v2-persistence.ts)；schema2，`sword-led.save.v2`与`sword-led.save.backup.v2`，同源仍只用`sword-led.writer` |
| 输入/声音 | 复用原生事件时间判定、重复/混合输入保护；身份增加rulesVersion/点位。声音仅在新接受结果后消费cue，显示/恢复不重播 |
| 原版 | `sword-led.save.v1`与原备份/forge-v1解释器不变；旧入口可继续，v2菜单可导出原始旧档 |

新SDK为`dist/sword-led-v2.js`，原core/session SDK仍可导入；构建会生成共享chunk，必须完整保留dist，不能只复制入口JS。此处没有全局测试控制器、注入钱包或强制胜利接口。

存档仍限制256KiB/2048动作/普通JSON，按种子从首状态回放所有接受命令并比较完整快照；伪造资源/次数/随机位置被拒绝。stock、requests、conditions、merchant四流独立，正常锤击不抽签。应力伤害来自公开阈值；遗物/事件条件和触发计数入档。买入/换下/扣两币为同一次命令，拒绝不先丢旧技法。

本次首次发布使用固定`forge-v2`参数。发布后若调整会改变旧journal结果的数值或机制，必须保留原解释器并采用新的规则身份/显式迁移流程，不可悄悄用新表重放用户旧档。T11.3原则上只派生D美术和完善界面。

## 策略验证怎样复跑

```sh
npm run verify:v2 -- --seeds 1 --out tmp/v2-smoke-new
npm run verify:v2 -- --seeds 32 --out tmp/v2-review-new
```

输出目录必须新建，已有目录拒绝覆盖。1种子为29组合的开发烟测；完整本轮为29组合×32固定种子=928局，耗时941.732秒。所有终态均用正式`validateRun`完整回放；[统计与源hash](evidence/T11-2/simulation/summary.json)、[真实胜利](evidence/T11-2/simulation/victory.json)、[真实失败](evidence/T11-2/simulation/defeat.json)保留。

后续T12.1已完成既有29组合各1000种子的原规模批次独立核对，见[29,000局审计](reviews/R4-v2-model-audit.md)。下段32种子数据保留其阶段身份；新批次没有更改forge-v2规则/策略，不代表真人玩法通过，也不覆盖待确认的v0.4新规则。

脚本不是最优玩家：轻锤策略固定六击且不回火；平锤策略对前两件尝试追加六击/各用一次煤；重锤尝试高锤力路线，热不足时可轻锤收尾。已达标可回收后件；选择委托/淬火/购买只看当前公开状态，不读取未来随机。三开局技法与相应路线一起变化，不能把通关差异全部归因于被动技法本身。

输入另用独立固定误差流：perfect为0ms，steady均匀±90ms，shaky均匀±190ms，并经真实锤法周期和`timingMarkAt`换算。它们是模型假设，不是测量真实玩家准确率。每组合32个种子；在shaky假设下，平锤三路线为22/15/23局通关，重锤为7/7/9局，后者平均锤数少、破碎更多。perfect/steady的平/重六路线均32/32通关；固定六击轻锤、原坯和全回收脚本没有通关。这不等于轻锤没用，更不能证明游戏已经好玩。

另有公开命令对照：巡锋齿改变同纹属性/价与订单奖励；回火砂让三击短配方满足原先不够韧的委托；桥脊扣让一把真实到达1完整/28应力的精钢剑可水淬，否则会破碎。这些是可达路径证明，不是替用户选唯一打法。

## 证据边界

当前阶段验证核心/存档/初始试玩。新版纯键盘首轮、真实三轮/首商人、原版与新版同锁/独立存档、危险预览、慢速、失败写入后导出真实内存进度等按真实页面执行；单测/策略数据和页面结果分别记录。原版真实缓存堆/原生输入继续回归；新版自身的原生缓存堆与最终完整界面矩阵仍须在T11.4专门证明。

最终美术一致性、完整D界面/全部状态、真人再玩与最大R4仍待后续，当前不标为完成。暂停不扣资源，不保存试玩会明确提示刷新丢失；旧档不会因进入新版自动转换或删除。
