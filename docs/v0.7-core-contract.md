## API 与状态所有权

`createRun({runId,seed,mode?,eligibility?})`返回独立v4初始局；`applyCommand(state,{runId,expectedRevision,action})`一次接受完整动作；`getRunView(state)`/预览给出所有条件、代价、可用操作和当前结果；`validateRun(unknown)`从创建参数与Accepted journal逐步重建并比对全部快照。拒绝返回同一原状态、零事件、零抽样；不冻结调用方输入。无DOM/存储/墙钟/Math.random。

phase为opening→workshop→summary→下一日；第4/8日存活收工先进入chapter，选一项改造后进入summary；第12日直接victory/return/defeat之一。opening的continue只开工，不发奖励；所有过场显示事实，动画不决定经济。一天总3新坯、唯一留剑、最多3手艺；不合格交付照原身价付金币但不计主委托，合格则自动交委托，无买家选择开关。

所有百分比为整数比例逐层向下取整，身价上限1,000,000,000、等级99；金额总量为安全整数。3配方倍率/风险、12任务、3改造、6事件与价格沿批准表，不重新定义。第一天40→58→84→121例对应有重锋资格时选重锋；新玩家默认轻刃40→62→96→148，仍三记无裂锤满足100目标。

## 主委托与去向

每项任务拥有一个或多个公开路线，每条路线有required数量和全部兵器条件。交付时满足任一路线基础条件的剑标为commissioned，记录真实commissionId/交付日；其他标sold。每条路线独立统计这些不可变交付，不锁第一条路线：第11日先交一柄新剑后仍可用一柄旧剑完成旧剑路线；未选路线的先前合格交付不额外发奖。已达标后的余剑只按售卖处理。最终选首个满足数量的路线及其最早交付剑作真实作品。

第5/11日旧剑判定为suppliedDay<当前日（能存活至本日必经昨日唯一剑架）；新剑替代判定suppliedDay=当前日。第8日两柄分别满足条件，不按总价凑数、不允许复用同一剑。收工一次判定完成/失约/护炉契，自动回收余下active非留剑的底价1/4；留剑、交付、交易、捐赠、旧刃交换、断剑均唯一去向。断剑自动回收，只有真实敲断且当时装备铁夹才留继承额。

## 配方和成长

所有新玩家可用light；创建资格可带guard/heavy，排序去重后的资格副本固化在局中。当前任务需要的配方自动借用；本局存活结完第4/8日后也分别解锁guard/heavy，跨局权限仍由炉谱保存。配方仅在这柄剑首记普通锤前可改，改配方不改变底价/身价/留剑风险或抽样；首锤后不可改。

普通锤计hits并积charge，安全连锻不加普通hits/charge，独立bursts每命令+1；前3普通锤0裂率。首次裂损保留剑，下一次裂损断剑。手艺沿旧6项；pardonUsed属于局，卸换不恢复。回响将普通成功（含大成）每第3次在配方涨价后乘125/100；裂锋+100/1000普通大成率，不改裂损。

风箱：安装后每柄的首次普通大成额外乘110/100；已经出现过普通大成的旧剑不追溯。宽口炉：每柄第一次连锻多1记，可与ember的1记叠加；下一次不重复。余温架：advance时唯一留剑乘115/100并更新peak，裂纹/charge不重置；每次真实跨天一次，挂取/重载不增加。改造在chapter选定、下一次advance后才可能锻造或跨天受益。

第4日提供风箱/余温架二选一；第8日提供尚未持有的两项（包括宽口炉），最多两项，无隐藏随机门槛。章末选择不依赖主委托达标，存活完成本章仍可改造；作品/渡口是否恢复等结果严格按真实主委托，不伪造救援。

普通底价=章节基础价乘已购升级的(3/2)^次数后取整；捐剑的次日120%随后计算，继承最后只加第一柄，最多当日普通底价4倍。升级仅影响未来供给，不改变当前剑。商人池第3日steady/ember/echo，第6日inherit/crackedEdge/pardon，第9日全部6项，各次从未持有者抽2且不重复，替换三槽原子操作。升级180/700/1600，修补150/350/800，均每访一次；免费首门仍steady/ember，双方都已持有时40金币，只有一次。

## 六个事件的确切时效

独立事件随机流先洗6项，每局第3/5/7/9/11日各取一项，无同局重复；当天接受或拒绝最多一次，未选择收工等同拒绝。守炉接受无资源变化，仍消费当天选择；拒绝始终合法。

- 捐剑：必须交当前active非留剑，不付卖价/回收/委托，次日三个新坯普通底价120%。
- 借锤：付60；次日第一柄前三次普通成功/大成的正收益额额外10%，在配方/风箱/回响结算后计算，不加成损失；过日不继续有效。
- 旧刃回收：仅接受当前唯一留剑，付玩家160金币、移除留剑、不能再交委托或换手艺。
- 赊护：按章90/180/360金币，存一枚全局首次裂损保价资格；有未用资格时不重复买。下一次完好→裂纹消耗，即使同时有steady也消费，不能免再次断剑。
- 修棚：付80；次日第一柄在该日的普通裂损率减30/1000、不低0，不减少大成率，留到未来后此效果过期。
- 守炉：保留全部资源。

以上次日效应只进入pending，在advance转为当日效果并清pending；不能经刷新或重复动作叠加。只有捐剑/旧刃交换接受时需要pieceId，其余接受/全部拒绝不得带无关pieceId。金额不足/对象无效拒绝整个动作。

## 终局、挑战和炉谱派生

印记0立即defeat；第12日存活且4/8/12关键任务均成、总至少10项完成为victory，否则return。最终任务成功但其他关键任务未成仍为return，叙事分别说明实际缺项。第4/8日存活收工记为完成章节（即使委托失约），可得相应配方；失败后仍可从合法历史派生这项成长。

`getCollectionAwards`只派生幂等集合：已结存活章节、配方资格、victory解锁challenge、实际完成的委托作品、合格名器（level≥9）的配方熟练、曾领取/交易的6手艺见闻。无跨局金币/数值加成、无领取命令或重复奖励，持久化在3i.2。创建资格是回放输入，不追读外部炉谱。

challenge需创建资格challenge=true；仍12日/相同判定和定价，第1–4日与关键8/12固定，分别在5/6/7及9/10/11内按独立内容流重排任务，保持章节门槛和商人日期。story永远批准的固定12任务序列。新玩家所需配方仍可借用。

## 边界与本任务验收

journal硬上限2048，1900起拒绝新锤/配方切换/挂新留剑/投资等可反复操作，仍允许取回已留剑、处置、收工、章末选择和推进，预留完整剩余12日出口。所有判断/模拟只通过正式命令；不以赋值钱包/阶段伪造witness。验证字节/对象/随机/动作幂等、12条件及替代数量、所有成长事件和结局。先小样真实全局/状态回放，1000规模/真人乐趣另验。

新SDK只导出纯核，不暗含未完成的存储入口。旧三版解释器/档/当前网页和全部旧证据保留，若构建重分块则当前旧SDK真实回放与必要消费者补验。正式预览不切成无界面v4，后续生产首章才升级页面。

## 复跑与消费者

先完成`npm run build`，再用`npx tsc -p tsconfig.v4-witness.json`编译独立验证策略（不覆盖旧tmp/simulation），执行`node scripts/v4-witness.mjs tmp/my-new-v4-witness`和`node scripts/v4-boundaries.mjs tmp/my-new-v4-boundary`，输出目录须不存在。策略只读公开预览，不看RNG或注入资源；首次成功只证明一条可达路线。

Node或浏览器模块可从`dist/sword-led-v4.js`导入`createRun/applyCommand/getRunView/validateRun`。创建后先发送`{type:'continue'}`，再发送`{type:'strike',pieceId:'d1-1'}`；每次命令绑定当前runId和expectedRevision。只向内核传入已创建或validateRun验证过的状态。展示按canSettle/canAdvance等当前动作旗标使用相应预览，已经结算的事实读取history；不在终局再执行收工。

局档/炉谱集合的读写错误、合并与跨窗身份将在3i.2实现。当前getCollectionAwards仅派生合法局的集合，无磁盘写入或领取副作用。
