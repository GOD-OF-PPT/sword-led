# v0.7 第一章界面实施合同

2026-10-20，3i.3；沿[已批准完整方案](v0.7-complete-game-proposal.md)、[核心](v0.7-core-contract.md)及[存储](v0.7-persistence-contract.md)。本项为生产首章：四天真实委托/商人/事件、渡口结果/改造与炉谱；不称全部十二天已完成。

## 场景与流程

标题使用行脚灯路原创场景，提供启程/继续/炉谱/设置与明确旧v3续玩链接，不自动创建新档。启程创建独立v4局→开炉情境（可立即跳过/点火）→workshop。炉前展示一个当日主目标、三枚印记/金币、一柄大剑、实物剑架/来客；主要动词仍敲、交、留、收工。规则/旅程/设置/炉谱按需展开，无默认多轴加工或一圈等权数据卡。

每日自动推荐配方，首锤前可改；recipe决定真实兵器家族，level决定五段外形，裂纹/断裂真实显示。目标条件及交付按钮读getRunView，不自行累计卖价冒充主委托。交付不合格仍能卖行会；回收/留剑/商人兑换各有唯一去向。首次完成主目标领取既有赠品，第三天真实商人和种子事件，所有价格/可用性来自纯核。

新MainCompleted可显示用途短场景，动画可跳；按真实委托/交付成品展示点灯、驿路、修炉，不发经济命令。普通结果有接触/火星/浮字与持久可回看的关键提示。收工明确回收余剑、保留剑、失约/护印和下一天；第四天真实章末显示渡口是否守住，选择风箱/余温架，之后“第一章已走完”收束。收束显示真实达标/遗憾和已选设施/护刃资格，不能叫十二灯复明；状态留在day4 summary，下一开发阶段可正常继续。

读档不补播交付/解锁动画；已有高于4日状态安全保留，只能回顾/导出/回标题，不能进入未完成页面。失败使用真实defeat和已取得炉谱，不假称通关。新局带已有合法资格，当前局资格保持冻结。原v3另开v3.html，v2.html/legacy.html继续旧解释器和档。

## 美术与可用性

固定新运行路径：lantern-road-v1.webp、bridge-dark-v1.webp、bridge-lit-v1.webp、modifications-v1.webp（三列风箱/余温架/宽口炉）、events-v1.webp（三列两行donation/loan/salvage/credit/shelter/rest），位于/assets/d/v07/。前后渡口构图保持同一地理位置。均为内置imagegen原创/参考派生，无嵌入文字/按钮/整图热区；PNG/prompt/引用/hash/alpha/尺寸与图集切片保存。新运行图目标≤2MiB；失败有文字/已有图回退，不能白屏。

1280×720和1920×1080优先，正文≥12px、关键目标/操作≥44px；主体与下中部留给剑。模态内容可滚动但行动区始终可见，keyboard焦点进出可恢复。正常保存收纳；主档、炉谱、设置各自错误明确，不把局存成功说成两档全成功。保存重试/显式备份恢复/导出/只读接手与不保存试玩全部是真实API；newGame的collection_pending保护不可绕过。

输入绑定runId/revision/generation/epoch，左键按下/Space松开各一次。模态/暂停/切后台/读档/销毁取消未完成输入和动效；Accepted已写盘不能撤销；静音/减弱动效与不补播保持。检查真实接触与受控慢帧，不以DOM盒或任意锚点代替锤面合理。
