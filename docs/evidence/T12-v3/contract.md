# 当前规则模型合同

规则为 forge-v3，使用现有 dist/sword-led-v3.js 和共享 SDK，离线工具不会接入玩家页面。正式批次 26 组各使用 v3-balance-0000 到 v3-balance-0999。每局仅通过 createRun/applyCommand，终态逐局 validateRun；最多 999 个 Accepted 命令。策略观察不含 seed、rng、journal、runId、revision 或未到账继承。

- 六组：保守/均衡/激进各选稳手或余烬赠品。保守在普通裂损率达到12%或裂纹时交差；均衡为30%或裂纹；激进为50%，允许带裂纹继续。已达到本轮差额则停手。蓄满六格的安全连锻优先于风险停手。
- 四组：每柄固定3/6/7/10次点击后交差，破碎则换柄；6次不包含第7次安全连锻，明确比较到达爆发前后的差异。达标后的保险剑仍按所有组通用的三次安全准备处理。
- 六组：以均衡+余烬为基线，分别去掉保险剑、交易、升级、修补、全部商人行为、全部手艺（赠品与交易）。去手艺组仍可升级/修补。
- 五组：只把商人排序首位改成回响/稳手/护印/继承/裂锋，其他同基线；赠品仍余烬，未宣称完整六手艺组合搜索。
- 两组：基线每命令重复提交旧revision；基线每次结算与每50命令JSON保存恢复。与基线1000行深比较（只排除profile标签），检查状态/RNG/收益无变化。这里的恢复是SDK回放，不替代浏览器真实localStorage/BFCache验收。
- 三组：原坯直接交差、全部回收、盲击到破碎或封顶；不领赠品、不买商人、不留保险。另核对1000个无操作初始状态保持workshop/零收益，不把不操作强迫为终态。

商人每访最多交易一次：付未挂起的最便宜实剑，只在空槽或偏好高于当前最差手艺时换；可买则升级、可修则修。保险在达标后将剩余最佳完整剑最多锤至3普通锤，并在它比旧保险贵时挂上；库存耗尽才取下原保险。此策略可能弱，不代表所有人会这样操作，也不保证随机流配对后的收益是单个手艺的纯因果估计。

独立审计重新列26组/种子顺序、配额和账目等式，重算统计、逐轮到达/达标和配对胜负，回放首个胜/败完整存档。生产器全局回放数与审计器仅两个witness回放必须分开记录。固定种子模型不证明真人可玩性、最优策略或所有概率空间；发现高胜率固定配方须作为设计风险如实记录。

复跑（先按README构建，已有tmp/simulation旧产物不覆盖）：

```sh
node --test tests/model/v3-model.test.mjs
node scripts/v3-model.mjs --seeds 1000 --workers 6 --out tmp/my-v3-batch
node scripts/audit-v3-model.mjs tmp/my-v3-batch tmp/my-v3-audit.json
```

输出目录必须不存在；1..1000种子、1..8worker；失败无summary，运行中不改src/tests/scripts/public/config/dist；每片25种子、最终按组/种子排序，不以worker到达顺序挑witness。正式运行前后全部源/产物指纹相同。原JSONL无损gzip和摘要、必要witness发布，冗长逐片日志留本机并记录hash。
