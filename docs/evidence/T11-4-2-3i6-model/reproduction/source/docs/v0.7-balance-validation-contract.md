## 规则与保存边界

当前forge-v4已公开，validateRun按固定规则重放旧journal。倍率、风险、报价、订单条件、随机调用和结局不在原身份下调参；若发现确需改规则，应形成独立身份/旧档兼容的具体提案，不能修改旧档解释器掩盖问题。本轮可修策略工具、实际引导和可读性，不添加永久钱包或假资格。D画风、直接左键及自然锤姿保持。

## 事前冻结的实验

正式每组同1000个种子：v4-balance-0000至0999。试跑使用不同前缀v4-pilot，不从1000正式集挑成功种子或事后拟合停止阈值。策略技术缺陷须保留原红和精确修补，再重新冻结正式输入；不得修改模型造出理想胜率。

故事组28条，均从新玩家light资格开始；qualified两组另用实际210命令胜利档正式回放所得资格，固定相同资格分别跑story/challenge，和新玩家样本分层。

基线商人：优先修印、再升级；每次到访最多换一门，至少留下两柄可用候选，三槽按公开偏好替换。免费技能只领一次。先完成/尝试当前主单，再处理可选事件、准备明日留剑和余剑；旧刃报价低于其可直接卖出的身价时拒绝，不人为挂剑只为触发交换；捐剑只选实际余剑，其他事件按公开负担能力决定。具体风险阈值、余剑次数、候选排序及后备路线在profiles字面量/策略代码中于正式批次前冻结，并在报告解释，不能事后隐藏调整。

策略只能收到白名单公开观察：当前phase/day/mode、钱/印、当前/明日纸单与公开供给、配方、当前兵器值/裂纹/等级/锤势/连锻和公开风险、手艺/改造/候选、商人价目/货架、免费奖励和事件报价。不得取得runId/seed/RNG/journal/eventDeck、未来抽样或可克隆试算的RunState；决策函数不持有kernel。事件报价由runner调用正式API，公开给策略；所有经济动作只经applyCommand，拒绝命令是模型错误，不算普通败局。有限上限1000接受命令，达到非终态上限立即失败。

完整配置作为独立纯数据依据保存在[v0.7-balance-profiles.json](v0.7-balance-profiles.json)。runner核对它与实际PROFILES一致，auditor只读取此数据核摘要元数据，不import策略；两者均把该文件纳入输入指纹。三十组包含镜像和负对照，不是三十种独立可玩打法。summary.traits统计终局仍装备的局数；曾装备和替换历史、实际触发及继承真正用到下一天另由完整journal审计。

## 产物与独立核验

新增专用MJS工具，复用现有正式dist/sword-led-v4.js；不覆盖tmp/simulation原21个编译文件。每组每片25局、最多8worker，正式6worker；必须等worker真实exit0才认结果，收到message不等于成功。输出目录拒绝覆盖。30组×1000=30,000真实终态，producer逐终态validateRun深相等。

流式gzip保留每局完整创建参数、journal、终态与状态hash、逐日记录/指标，不只存摘要或首胜。独立auditor不得import生产策略或统计函数，须独立重放全部30,000终态、重算逐命令账目/印记/供给/唯一去向/条件/成长与全部统计；分别报告两次回放责任。代表witness按profile固定顺序、seed最小值选每种真实结局及内容特性，不按worker完成顺序；没有的类别明确记0。定向补证单列，不计进1000统计。

实现试跑使用v4-pilot前缀，须单worker与多worker逐行一致；策略冻结后另以v4-balance-0000/0001做正式输入preflight，主批前两种子须与该冻结对照逐行一致，此对照不用于拟合策略。额外试跑前缀不混入正式30,000。duplicate/reload与balanced-ember排除profile标签后深相等，包含RNG/状态hash/完整统计；这不是浏览器缓存堆证据。

## 必报指标与拒绝检查

- 三结局、12/12、关键失约/护灯已成、每委托进入/完成/路线/候选与普通锤/连锻/裂断；区分到达后完成率与全样本比例。
- 接受命令/strike点击/内部锤分别计；金币/印记/峰值/上限、p10/p50/p90/max；回收、卖行会、委托、交易失剑价值、修印/升级成本均独立对账。
- 留剑/取回/跨天、余温实际增值，三配方/六手艺/三设施的装备与真实触发；六事件出现/接受/拒绝/不可负担/后果消费；成长用途不能只数按钮出现。
- 同种子胜负转换表、命令/达标差和分层资格；不同动作会改后续抽样，配对不是单独手艺的严格因果。
- fixed-7需同时看victory和12/12。固定7若≥95%胜且成长/留剑消融差异很小，记为退化警报；不能用第2和9单条件不同就声称反退化已过。第9双连锻非关键，必须报告放弃/强追及第12机会成本，不把可跳单当全局强制搏命。
- 所有路线/三结局、三改造、六手艺、六事件和效果消费、章节后失败及挑战重排均要真实命令见证；缺项继续定向调查，不强造成功或归因实现失效。
- CLI未知/重复/缺值/越界参数、已有目录；坏gzip/缺行/重复/乱序/错seed/profile/mode/非终态、账目/路线/计数/奖励/触发篡改、journal/资格篡改、伪源/SDK指纹（即使同步重算摘要hash）、镜像深字段/RNG漂移、worker发消息后失败均须拒绝；失败不得产成功summary。
