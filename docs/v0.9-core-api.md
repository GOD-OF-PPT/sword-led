# forge-v6正式核接口

2026-10-23，按已具体批准的[短段方案](v0.9-sword-expedition-proposal.md)实现。正式SDK为`sword-led-v6.js`，旧SDK语义独立保留。此文档描述接口，不证明真实UI或趣味完成。

- `createRun({runId,seed})`：返回`{ok:true,state}`或`{ok:false,error}`；不接受初始金币、剑、工具、战力或旧资格。seed按NFC与首尾空白规范化，runId为安全长度标识符。
- `applyCommand(state,{runId,expectedRevision,action})`：只接受当前规则、局与版本；拒绝时返回原state引用、空事件和字符串error。成功一次增加revision与accepted journal一次，返回冻结state及真实events。state参数应来自createRun/validateRun/前次Accepted；不把任意外部对象当可信状态。
- `getRunView(state)`：只读正式风险/确定技法/当前动作资格、伤害与磨损、三回合清门路径和取匣条件。预览不抽RNG、不消费回合/资源，也不透露下一张随机票。
- `validateRun(unknown)`：先限制纯JSON、字节数与journal长度，再从seed与逐条正式命令完整重建，所有字段精确比较；额外字段、篡改强度/钱包/充能/奖励/随机位置或非法journal均拒绝。

规则动作只有：选流派`chooseSchool`、落锤`forge(useTechnique)`、放弃当前坯`discard`、收锻`seal`、架剑`guard`、斩主目标`strike`、直接争匣`takeCache`、离开取匣`leaveCache`、工具追斩`followUp`。下一锤技法标记只属controller临时意图；直到实际forge命令才消费，切剑/暂停/离页取消临时标记不改Accepted。正式动作字段和phase类型以`src/core-v6/model.ts`为准。

阶段按`main-forge → main-trial → cache → echo-forge → echo-trial → recap`，主关失败有剩余坯则回main-forge，无坯则failed；无工具可直接recap。Nail成功后只有一次echo-recharge回炉，在另一个新坯真实消费后recap，没有再开试锋/补给/奖励。Rebound主靶击破却无正溢出或无余回合时直接记录演示未完成并recap，不会卡在已死靶上，也不新增副靶普通斩来替代工具。工具净回充0仍记录触发，但不冒充净回充1并实际消费的成功演示。

普通锤每记抽1票1000等分，前三记概率阈值0仍前进随机流；之后完好200、已裂350，技法确定结果不抽。每柄6记、两炉各三坯/共享1充能；试锋先以动作前强度算伤害、再磨损/耗回合、再优先判断击破。取匣不接受架剑，条件不足无副作用。主门15铜钱每局一次，工具和尾声补给也只出现一次；所有结果与状态都可从journal重建。
