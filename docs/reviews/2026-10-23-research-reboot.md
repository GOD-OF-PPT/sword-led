## 研究如何落实

完整[研究报告](../research/2026-10-23-forging-gameplay-guidance.md)提供每条直接单评、时间/版本限制、正面反例、源码事实、具体改法与失败观察。80条是按推荐倾向对称设计的固定样本，不是好评率或用户共识；官方首图每款只看一张，没有宣称亲玩竞品。

本作当前最值得改变的是“重复同一锤到门槛、超规格成品用途不足、被动成长未改变操作”。炉前优化改善看到/理解的过程，不能单凭更漂亮宣称这些领域问题已解决。具体v0.9推荐为[《一剑开路》](../v0.9-sword-expedition-proposal.md)：先做含两主动技法、同剑开路、额外工具真实用途和失败调整的短段，不先扩更多订单/章节。

- 一锤只保留一处主结果：正式Hit的普通/大成/裂纹/断剑、跨视觉阶段名、本记总估值变化、真实生效手艺；安全连锻按实际接触逐记点亮，结束汇总实际已落下的估值差。不拆造Hit未提供的分项收益，也不增加经济动作或音轨。

## 本轮实际验证与修缮

按“交互/界面/玩法优先，测试兼容最低”只做必要有界检查，没有重跑384、全音频/性能/原生或1000种子。

1. `npm run build`：严格TS与全部网页/两个正式SDK构建成功。最初新模块闭包中的nullable推断错误保留在本地运行输出，已改为检查后明确非空HTMLElement，修后构建通过。最后源码与不可变快照由[manifest](../evidence/2026-10-23-research-reboot/manifest.json)固定。
2. 一个独立4259端口、独立上下文的现代Headless Chromium。真实左键从新局`v5-economy-0`开炉，8次普通命令覆盖普通、大成、两记安全连锻及首次裂纹；每次接受结果与构建出的正式SDK逐对象相等。8次均检查pointerdown已接受且接触前主结果仍hidden；连锻只在实际接触后点亮全部格，未生成旧body成长标签。两PC尺寸1280×720/1920×1080实际截图并人工看图。
3. 点风险文字不产生领域命令；打开报价不改变保存事实并清旧结果；同一合法进度经classic及focus导航保持；途中Escape取消表现但已接受一锤保留，之后等待没有补锤。
4. 在同一新局继续到第二裂真实断剑，核“上一柄”提示；切新坯清旧结果，三锤合格后真实交剑/实收，领炉心余烬、留最后一柄、收工、推进第二天。每个这些UI命令继续核正式SDK状态一致，次日实际一旧两新，无额外来料。
5. 页面异常和HTTP≥400均为0；[浏览器结果](../evidence/2026-10-23-research-reboot/browser-result.json)保留前8锤真实事件/逐记表现，后续交付与次日检查由本地实际运行`focus-play-03.mjs`中的assert完成（报告数组不冒称记录全部后续命令）。局限明确：这不是真人趣味反馈，也没有新做完整十二天/长单双剑矩阵。
6. 只读独立复核检查真实Hit/接触所有权、run/revision/generation/epoch/piece守卫、cancel/dispose与classic分支；指出的读数穿透、裂纹承诺、上一柄语境三处已修。新结果无自己的timer/rAF/listener，不参与RNG/报价/保存。

当前订单/报价仍消费Accepted终态view，只有剑旁新结果保证按接触披露；不声称全UI都改成逐接触投影。兵器仍是已有三家族五阶段，低阶原画已经较完整，这一资产局限和玩法重复均保留，不以新背景掩盖。

## 新规则具体确认与产品剩余

v0.9提出新强度、主动干预、回合试锋、一次性关卡酬劳及工具分支，必须按原用户“确认实施文档”和祖先OpenSpec `AGENTS.md:13`“Do not start implementation until proposal is approved”取得具体批准后实施。这条边界仅约束新核，未阻塞本轮已授权的画面/反馈交付，也不是Game Studio新增的许可要求。

提案的手算复核指出了两条确定性免风险取工具路线及过门后再探隙的旁路，已在确认前改成基础通行可稳妥、争工具需至少一次有风险普通锤、匣子阶段只直接尝试/离开；尾声也写成唯一失败出口。格式校验和手算只说明规则稿自洽程度，不能当已经玩过或一定有趣。

**仍待解决：玩家对核心趣味和视觉的最新评价是否改变。** 当前新界面没有实现试锋，也未证明愿意重复打造。后续批准的核心切片应看能否为不同用途主动改变计划、失败后试不同解法，而非以新截图/测试数量宣布“目标完成”。
