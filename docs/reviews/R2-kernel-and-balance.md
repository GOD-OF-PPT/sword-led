## 整局模拟结果与平衡判断

正式集合为 verify-v1-0000–0999，每场景1000种子，共53场景/53,000行，包含52,000个终局与1,000个无操作初始状态。全部状态通过完整回放；逐步不变量没有失败，没有策略卡局。执行 Node v22.12.0、darwin/x64、6个数值线程，墙钟1094.766秒。最大日志630条，最大状态46044字节，均低于存档限制。原始压缩CSV、源码及配置/证据哈希已独立核对，见[核验记录](../evidence/T06/verification.json)。

锤法对照均为同一均衡策略、heat购买顺序、普通速度，每格1000种子。下列时长**只含按住与每击450ms反馈假设**，为胜利局均值，不含阅读/经营/思考，不是完整真人时长。破碎比例为所有已结算铁件中破碎数；它还受策略提前交货影响，不能只据此推断单击风险。

R1-04 的结论：在本模型下，轻锤稳健；标准/重锤通过更少操作和较短胜利局输入时间提供实际用途。高准确率轻/标准/重锤分别需257.6/170.4/130.8秒，但通关率为100.0%/98.7%/70.5%。不存在轻锤在这些指标上全部支配的结果，因此本轮保留原数值，不为做出好看胜率而调参。这里的1000/1000只描述该集合，不承诺任意种子必胜。自适应是固定启发式，结果也没有证明它最优。真实动画时长与操作手感仍由网页验证。

经营与辅助对照均使用均衡自适应，其余同上；购买顺序不是互斥流派：

| 操作模型 | 设置/路线 | 通关率 | 平均达成终结轮次 |
| --- | --- | --- | --- |
| low | heat | 11.0% | 10.86 |
| low | heat +1.5倍慢速 | 46.7% | 11.68 |
| medium | heat | 81.9% | 11.95 |
| medium | heat +1.5倍慢速 | 94.1% | 11.99 |
| medium | precision | 81.6% | 11.95 |
| medium | stability | 82.6% | 11.95 |
| medium | none | 1.5% | 10.58 |
| high | none | 28.6% | 11.72 |

各升级优先顺序都有正式通关路径，不购物也非绝对不可能；中等误差时其胜率仅1.5%，说明回收和投资有明显用处。保守策略多数情况下三件均交货，废料少，后期升级不足；它的低胜率描述这个具体启发式，不等于所有谨慎玩法不可行。激进策略和全部53场景的收入/消费/废料/购买/时机分布/逐轮记录均保留在原始JSON，没有只选通关数据展示。

中等误差均衡自适应前三轮达标为1000/1000、998/1000、997/1000；第十二轮960局到达、255局达标。总体819局通关仍包含合法违约容错：完成契约期不等于所有订单达标。前期宽容、后期压力增长在模型中成立；终局页面必须如实列达标/违约轮数。该曲线是否让玩家满意仍待真人反馈。

滥用结果：原坯交货与纯回收均0/1000通关、第三轮失败；盲击重锤0/1000、平均第7.01轮失败；无操作1000局均revision=0且无收益。重复旧指令组与正常中等误差组1000对状态哈希完全相同，通关同为819/1000；每个Accepted之后五次重发均拒绝。不能将盲击在该集合为零外推成数学上的永不通关。

真实整局证据：中等误差胜利种子verify-v1-0001，336条Accepted、十二轮、最后1枚印记/3268金币；原坯失败verify-v1-0000，14条Accepted、第三轮印记0。两份witness分别由独立CLI重新跑策略/输入并比对完整快照及指标，均通过；无赋值钱包/强制成功/注入胜利。

## 规则与边界全面检查

- 来料、锤法、三档时机、预击风险、低热/应力/升级、进度封顶、裂损/破碎、交货/回收均核对同一公式与视图。0热禁止，正余热允许最后一锤，热耗钳到0；该已有规则使阶级阈值与不同锤法存在实际取舍，没有为模拟私改。
- 经济检查金币=收入−消费、废料=回收/破碎−消费；历史仅记结算轮，不双计当前件。煤按日配给重置；每轮三件、终结不可逆、商人不补坯；两货币扣款原子且每访限购。
- 日终只有明确结算后推进；不足仅扣一印记，0优先失败；第12轮有印记为通关，未强制全12轮达标；终局无商人/13轮/重复奖励。没有现实时间倒计时，无操作停在第一轮是设计行为。
- 拒绝命令保持原对象、随机位置、revision和空事件；重发压力每个Accepted后五次，均拒绝；重发场景与正常对照逐种子状态哈希相同。
- 合法命令上限有资源证明：每件初热100，每煤再给不超过100；轻锤最低热耗8，因此每轮至多 `3×13+3×13=78` 击，十二轮至多936击；另加36加热、36处置、12结算、11继续、3离店、12交易，总1046为宽松上界，低于2048日志限制。没有无限加热或收益循环。
- 外部档用有界纯JSON/版本/完整 journal重建，未知字段、伪造钱包/随机位置/历史等拒绝；getter不调用，深度/节点/字节限制保留。本地单机一致性不冒充联网反作弊。
- 存储复核 workingBase 与读缓存分离、激活时禁止输入、generation与activationEpoch分开；主档失败保留dirty，重试不重击；备份损坏/读失败不能取得新覆写基准；原生独占锁和BFCache再读路径保留。完整存储合同见[T05](T05-persistence-validation.md)。

## 工程、安全与剩余责任

依赖锁与运行规则版本未变，无新运行时依赖。生产内核无 DOM、存储、墙钟、Math.random 或网络调用；模拟器与测试不进入 Vite 生产库。新增脚本仅写指定证据文件，不访问玩家 localStorage。审计未发现依赖漏洞，OpenSpec strict 验证通过。

实际工程检查：`npm run check`退出0，9文件/150测试、两份strict配置与生产构建通过；`npm run test:storage:browser`退出0，8项通过，含本轮[原生BFCache证据](../evidence/T06/native-bfcache.json)。三份SDK产物哈希与T05相同，说明新增模拟未混入生产库。依赖审计0漏洞；私有仓库/default main已实查。输入原文SHA256未变，9图/全部prompt哈希与B选择不变；新增源码/证据凭证模式未匹配，未保留临时搜索测试或生成器。

本轮质疑循环已修复类型检查发现的suite返回值推断、跨闭包状态收窄两项问题，未关闭严格选项；正常回放、样例及非法/重复路径均通过。没有为了通过测试删掉场景、改成钱包fixture或把最终轮违约改判失败。

R2 的通过范围是正式内核可达、资源守恒、确定性、存储回归与建模策略对照。玩家网页、两种尺寸、键鼠单击锁、实际静音/慢速/暂停/恢复提示、音效、视觉和真人反馈仍分别归 T07–T11；最终全项目审查归 T12。12–20分钟时长、可理解性与乐趣尚无真人数据，不能据脚本结论承诺。
