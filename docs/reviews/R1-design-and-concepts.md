## 2. 规则、流程与资源逐项检查

| 检查 | 结论与依据 |
| --- | --- |
| 来料与机会数量 | 每轮恰好三件，首轮固定；后续第三件概率合计 100%；商人不卖第四件；件 id 按轮次区分 |
| 玩家行为闭环 | 选件/锤法 → 蓄锤/落锤 → 成功或裂损 → 继续/加热/交货/回收 → 结算；零热/无煤/满阶均可交货/回收，不堵局 |
| 升值与破碎 | 阈值递增、进度封顶 35、价值使用整数倍率；裂损与破碎不同，完整度 1 时本击破碎概率等于裂损概率 |
| 资源账目 | 交货入金币且计当轮配额；回收/破碎入废料而不计配额；商人双货币一次扣；煤按轮重置，不囤积 |
| 配额与惩罚 | 只看当轮实际交货；提前收工仅回收余件；少于配额只扣一枚；不追回金币、不追加债务，终结状态不反转 |
| 日终与终局 | 三件完不自动扣印记；结算一次；0 印记优先失败；轮 12 存活为完成契约期并如实列违约；无 13 轮 |
| 商人 | 第 3/6/9 轮结算存活后进入；已失败不能买印记；每商品每访限一次、上限/余额可判，风箱下轮配给生效 |
| 保存恢复 | 每个 Accepted 动作尝试存档；版本/结构/语义校验；dirty/重试不重做动作；日终 history 不双计当前件 |
| 时机与输入 | 整数标记、松开时间判定、双随机流、唯一 attempt、取消不抽样；重复/过期命令不变更资源 |
| 生命周期 | 教学与正式局隔离；失焦/换锤/设置取消；旧 generation 回调失效；第二写窗口与 bfcache 有明确方案 |
| UI 全流程 | 菜单、教程、工坊、处置确认、提前收工、日终、商人、终局、暂停、续玩、异常均有入口和出口 |
| 规格/验收 | 四能力 21 Requirement /45 Scenario 与 44 项验收矩阵匹配；实施检查未提前勾选，规则真相不散落 UI |

以上为设计合同检查，不是相应实现已存在。原生浏览器能力的官方依据与版本核实留在 [工具依据](../technical-sources.md)。

| R1-04 | 高精准率下轻锤单位热耗/应力/风险可能支配其他锤法 | 实施方案/AC34 明确固定轻/标准/重锤与自适应跨种子对照，连同次数与操作时长比较 | 后续验证项，T06/R2 负责；未冒称已修平衡或通过 |
| R1-05 | 矩阵/README 的“全未执行/待生成”已落后于本轮文档与概念进度 | 更新阶段文字与可审阅链接，区分资料/图稿、代码、模拟、浏览器与用户反馈 | 资料一致性检查通过 |

240 账目的矛盾：若不修补，前五轮仅一次违约，则至少四轮达到最低配额合计 660；加本轮交货 144、减锤柄/砧台 260 后钱包至少 544。若第 3 轮商人修补一次，购买总计 500，前三轮必须先赚够 500，轮 4/5 至少一轮达标 ≥210；加本轮 144 后钱包至少 354，仍不可能 240。

修正账本：轮 1–5 交货 136/155/183/227/0，第三轮买锤柄与砧台共 260，轮 6 先交熟铁上品 144，钱包 =585；废料 `4+3+3-9+3+1+1=6`，轮 5 违约一次后印记 2。精钢三次精准标准成功、两次裂损后，进度 9、热度 40、应力 47、完整度 1/3，精准风险 14%。这是资源/公式可行性，不是已经跑过的游戏回放。
