## Context

当前v3纯核可回放、单写/恢复/输入取消已经具备，用户否定的是游戏整体内容。新主线改变原累计计价与状态阶段，因此保留原解释器，独立v4，避免将UI投影包装成新规则。

## Decisions

- 使用类型化静态内容表：12主委托、3配方、3章节、3改造、6事件；条件与奖励仅由纯核判定，DOM只显示同一个公开预览。
- 新chapter/ending阶段有实际用途场景与跳过/继续；Accepted后果先保存，动画只消费差分，读档显示事实而不补播。
- 主委托自动识别合格交付；不合格可正常卖给行会，明确不计目标。唯一兵器去向和限次选择仍由核心保证。
- 局内三柄、唯一留剑、三手艺、固定商人；三配方首锤前决定，避免逐锤设置。
- 炉谱只用幂等解锁/作品集合，无跨局消耗货币。创建新局冻结解锁快照，合法journal回放不依赖当前炉谱；局档保存与炉谱写失败分别显示，重试可从合法历史恢复集合。
- 初始数值与全部条件以v0.7文档为唯一提案表。实施验证发现冲突应修正文档并说明，不静默发布不兼容结果。

## Risks / Trade-offs

条件任务可能逼迫搏命；旧剑任务提供新剑替代，关键配方借用、不依赖随机商货，并用1000种子/真人首章同时验证。新模式增加内容维护成本，以数据表完整性/ID唯一/引用与实际渲染覆盖检查约束。炉谱不是双档事务，禁止消耗型跨局资产，并明确两个保存状态。

## Migration / Rollback

v4独立主备档和入口，原v3可在标题继续；不改旧档和SDK。回滚使用新增revert及保留预览。确认后先独立内核，再生产第一章、其余章节/结局；第一章仍标切片，全部内容和最终验收完成后才称完整交付。
