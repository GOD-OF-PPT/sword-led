# v0.3 技术与验证设计

[完整提案](../../../docs/v0.3-gameplay-proposal.md)定义状态、整数参数、执行样例、验收、风险和回滚。此文件只记录工程边界，防止双份规则漂移。

1. 新规则纯函数集中core-v2；UI/试剑只读view，不复制结算/委托判断。参数表同供正式命令、预览与模拟；journal验证必须正式回放。
2. 保留v1核心与公开SDK默认契约，新增适配口复用会话/存储；新档key/schema与ruleset显式区分，旧档不自动转换，两模式共享writer锁。旧模式可继续/导出。
3. 事件与候选使用独立种子流；用户可见动作只在accepted时推进对应状态。选择落点、播放试剑、打开作品簿/设置不写journal或抽随机。
4. 规则变更按T11.2、完整D资源/界面按T11.3、跨引擎/真人再玩按T11.4，goal总体仍保留T12最大review。先前三轮验证核心，再补齐十二轮；旧测试/旧53,000模拟不得冒充新规则证据。
5. 输入票据包含ruleset/runId/revision/generation/activationEpoch/点位/锤法，后台/暂停/换点/换锤/恢复/切模式取消在途动作；旧动画和试剑不影响新局。
6. D背景、器具、肖像用独立栅格；五节轮廓/点位/纹路由真实状态的代码图形绘制；DOM承载可编辑文字与键盘控件。静态层可缓存，避免每帧重绘整幅大纹理。
7. 先验证有差异的三轮真实UI与存档，再检验十二轮策略和功能矩阵；真人仍觉得单调时继续修核心，不靠增流程/图稿/测试量替代。
8. 回滚用revert+旧模式/旧档，保留v0.2快照与全部原图；不重写Git远程历史。
