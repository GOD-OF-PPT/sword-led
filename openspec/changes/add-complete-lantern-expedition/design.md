# 完整旅程的实现边界

[正式玩法／内容／数值合同](../../../docs/v1.0-lantern-expedition-proposal.md)和[实施顺序](../../../docs/v1.0-lantern-expedition-implementation.md)为唯一具体候选。本文件不追加第二套规则。

## Decisions

- 新core-v7拥有三章九节点、双剑所有权、锻造随机、压力／行动、工具、剧情事实、灯芯归属、钱与结局。正式view给UI当前地点、约定、人物反应、合法操作、下一目标与代价，不让renderer推算剧情或发奖。
- 复用generic session/repository/input生命周期；schema7、save.v7/backup.v7/writer.v7、sword-led-v7.js独立。v5/v6解释器与SDK字节保持，新模式不导入旧资源。
- 章初重整恢复当前章的正式可玩字段，失败历史与已用重整次数保留；起点来自journal建立并完整回放核验，不能携带本章奖励倒灌或无限重掷。
- 同行炉台DOM/Canvas适配锻造、守护、救援、机关、营地、接力和终局；一次一个情境，当前约定与灯路直接可见。D资产按真实前后状态复用，独立分镜不读游戏档，不冒称已可玩。
- 完整主线实现后切默认首页；旧v5保/forge.html、/classic.html，v6保/v6.html，显式新入口/campaign.html。不可变预览与新增revert回滚，不清档／强推。

## Risks

九次改名的同一算式仍会无聊；所以节点必须兑现不同目标／对象、伙伴帮助、同剑磨损与献剑、工具跨关用途。数量、规则正确和漂亮地图都不代表真人乐趣。数值目前为候选手算，实际有限完整路线若暴露断路必须修，不改消费者期望掩盖。

测试／兼容优先级最低。必要有限规则／保存／一个现代PC完整不同路线与分支即可，不重新启动旧384／1000种子／全音频原生矩阵。
