## Context

已发布forge-v2的journal依赖十点/时机/淬火规则。用户不满意默认玩法，要求深入参考ForgeTax优化。新方案需要独立规则身份，不能改旧公式使原档回放失败。完整规则/初始参数和算例以[文档](../../../docs/v0.4-gameplay-proposal.md)为准。

## Goals

首次进入直接能落锤；一次动作清楚产生身价/风险变化；停手、留剑和牺牲剑有有限资源代价；商人不增加每锤步骤。先用前三轮验证人的体验，再做完整平衡。

## Decisions

1. 纯命令`strike`只携带当前run/revision/剑身份，没有时机mark/落点/锤型。普通锤一次抽样；满势连锻在一次原子命令内产生2或3次安全抽样，逐锤触顶后停止。表现晚到不改变结果。
2. 同一件剑有唯一pieceId、原供应轮次、当前/底价/峰值、等级、裂纹、普通锤次数、锤势与普通成功计数。reserve只引用同一件可用剑，处置结果不可逆；每轮最多3新剑加1上轮保留剑。
3. 复用现有种子随机工具，锻造与商店独立随机流。报价首次生成即保存；切换、开关菜单、恢复、取消不重抽。
4. schema3/forge-v3使用独立主备key；`SaveCodec`接现有generic session/repository和writer锁。正式validateRun从初态逐条回放并比较全状态；旧解释器保留。
5. 投影显示主按钮本次风险、连锻结束后的普通风险、当前身价与涨幅、差额、剑去向和触发原因。DOM不复制概率/计价公式。D场景复用，不重新选风格。
6. 输入沿用已有单次意图/混合输入排重/epoch与后台取消合同；普通点击与Space松开均一次，接受前按下只抬锤。读档不补播旧奖励，静音/减弱动效保留。
7. 切片与完整模式显式区分。第3轮存活进入体验结束页，失败优先于体验结束；不能标为十二轮胜利。后续完整模式继续原十二轮目标，配置写入新局身份，不靠URL切换旧局规则。

## Risks / Trade-offs

- 简化操作可能退化为重复抽签：用可见两段损坏、充能爆发、保险剑与剑换构筑产生可解释取舍；最终由真实试玩判断，不能用大量模拟反驳负评。
- 首轮安全锤用于建立反馈；后续风险上升。初始曲线尚未平衡，不能宣称十二轮合理。已公开forge-v3参数后调整需明确新规则身份或兼容策略。
- 一次爆发多事件易重复计钱/重放：内核原子结算，Accepted序号与已播放身份分离；后台只取消表现。
- 留剑易洗风险或复制：只有一个保留引用，不改变剑状态；结算显式列去向，消费永不兼得交差/购物/回收。
- 研究不是亲自试玩竞品，关键帧与自动字幕有观察局限，已在来源索引逐条标识。

## Migration / Rollback

没有旧档自动迁移。旧D细锻和B契约继续用各自入口/codec；新默认页面明确新玩法。不能读新档时保留原字节、提供备份/导出/不保存体验。回滚仅revert新增默认接线，保留新存档与新旧快照。
