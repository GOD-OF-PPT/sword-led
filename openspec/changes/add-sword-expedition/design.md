## Context

默认首页仍为forge-v5/schema5三章十二天，保留旧版本解释器与图源。用户此前反馈明确认为游戏无聊、视觉缺乏吸引力；本变更从“剑的制造选择→使用后果”重做短循环，而不是再只换文案或补订单。完整合同见[方案](../../../docs/v0.9-sword-expedition-proposal.md)，已于2026-10-23[具体批准](../../../docs/approvals/v0.9-2026-10-23/approval.json)。core-v6、schema6、独立v6入口及短段已实施，待本轮发布回执；实际证据见[工具闭环](../../../docs/reviews/v0.9/3.1-tools-review.md)与[必要边界](../../../docs/reviews/v0.9/3.2-bounded-checks.md)。本文件原数值／流程算例仍保留历史手算身份。

## Goals / Non-Goals

- Goals：一个约90秒短段中出现有限主动锻造、两实际不同打法、同剑试锋、超规格第二用途、工具第一次真实使用和可调整失败。
- Non-goals：完整十二章、新实时战斗引擎、QTE、十点／工具／温度多轴、永久战力货币、旧档迁移、默认首页切换、全兼容／模型重跑。

## Decisions

### One new capability and isolated rule identity

已采用core-v6纯核、rulesVersion`forge-v6`、schema6、独立主备key／SDK／`/v6.html`；v5继续原合同，首段不导旧资格／金币／剑／炉谱。保现有TS/Vite、DOM/Canvas、session/repository边界；不迁引擎。新随机流只服务普通锤，每次普通锤抽一次，主动确定技法不抽。整数与全journal重建约束沿现有安全模式，新核不信任存档快照。

### Finite state machine

`new → forge(main) → trial(main) → optionalCache → forge(echo) → trial(echo) → recap`；无工具者optionalCache后直达recap。主炉失败可回forge选择剩余新坯，三坯耗尽则failed。主门通过后不回主炉／再领奖；尾声只有一次新三坯／1充能补给，无金币／工具匣。尾声锻造期放弃／破碎可选剩余新坯但不返充能；尾声试锋一旦提交就只有该柄一次3回合，回合耗尽未完成直接recap，不重置目标／回合／探隙／追斩／工具触发再试。练习失败不撤主门结果。主炉和尾声库存／回合／触发分别标识，不能跨阶段偷运新坯或重置已付门。

每柄记录id、流派、强度、锤数、裂纹、是否实际崩纹、封锻／失败／破碎状态。首炉／尾声各有0或1技法充能；每次新坯首锤前选择流派，之后锁定。失败／放弃剑保记录、不再提交，换坯不返充能。试锋同次不能换剑；主炉失败换新坯时卫机耐久归6，旧伤害不累计。崩炉尾声首甲靶击破后只开放一次`forge(echo)`回边，以另一尚未锻新坯实际用回充；该记成功即recap，不再开启试锋，不重置供给／目标／触发或返回主关。若无剩余新坯则记回充发生但再次使用未展示，不补第四坯。

### Controller intent versus accepted command

“下一记技法”标记只属于controller临时意图，绑定runId／revision／generation／pieceId／流派。取消／切剑／收锻／暂停／隐藏清标记，无RNG或经济写；实际forge命令明确是否用技法，纯核验证当前充能／流派／裂纹／锤数后一次消费。旧事件／key release不能把意图用到新剑，已Accepted后取消动画不返还。反复标记不写journal，不产生免费刷新资源。

试锋正式动作按阶段白名单：`trial(main)`接受斩击／架剑；`optionalCache`只接受直接工具目标尝试／离开，拒绝架剑／再斩主靶／换剑且不耗回合；尾声按其固定目标与分支接受动作。主门击破斩已消费探隙，进入取匣阶段无探隙／临时伤害加成，不能让安全崩纹6过门磨到4后再架剑把铁闩伤害6加到8。renderer不能决定命中、随机、耐久或收入。展示动画可取消，结果保留；reload重建事实不自动补动作。

### Exact resolution order

锻造先验证身份／阶段／可用坯／锤数，再确认普通或技法；普通抽1票，主动技法不抽；结算强度／裂纹／充能／锤数后记录事件。技法锤也计6记上限，定线不修裂纹，崩纹只对完好剑，普通裂纹不自动变崩纹。

试锋先验证目标／回合，再用动作前剑强度计算伤害；斩击消耗探隙，崩纹斩后磨损2；回合只扣1。先判目标耐久≤0并发一次过门／15钱，再判回合0失败。取匣阶段强制opening=false，不把对卫机的探隙搬到固定物件、不返资源；铁闩普通直击max(0，强度−2)、崩纹直击强度＋2无视甲，无探隙加成。工具匣条件不足为拒绝，不耗回合／磨损；成功后本段工具槽关闭。回锋追斩单独耗1尾声回合，伤害只用先前正溢出，不再套剑／护甲／探隙加成、不链生新追斩；崩炉钉只在尾声首个带护甲主靶首次击破回充一次，上限1。

### Reward proof is in scope

只在道具卡写“下一段生效”不足以交付核心闭环。主门基础稳锋4／崩纹6可以无随机风险过门，但吊索改完好≥5、铁闩改实际伤害≥7，使额外工具至少要求一次普通风险：稳锋第4普通成功后第5定线5；崩纹第4普通成功后第5崩纹7，过门9磨5、打闩7。该普通锤20%裂损；先刻崩纹再补普通则35%二裂，预览须区别。旧首稿门槛4／6会安全必拿，已据独立静态反证修正，不当有趣的实测结论。

工具尾声不抬高门槛：回锋主靶2／甲2、副靶4／甲0、3回合；完好4剑探隙打6、溢出4追斩。崩炉尾声主靶2／甲2，先在新炉实际用崩纹消耗充能，破靶后回充，再在另一新坯实际消费。尾声不付新钱／掉工具；没演示成功就不声称工具实际使用已通过。

### Visual and evidence ownership

真实Accepted驱动连续亮刃／崩纹裂隙、盾受力／破绽、吊索切断／铁闩破坏、工具领取和追斩目标选择。减少面板与永久术语，强度／裂纹、3回合和当前下一动作常显；细则按需展开。保原D来源，可复用资产但不得让旧整图冒充新交互；新增资产保prompt／原图／来源。

## Alternatives considered

- 仅提高估值奖金／取消钱袋：仍无锻造表达与用剑后果，且重启货币膨胀；不采用。
- 全自由造型工具：创作自由可吸引部分人，但不保证游戏性，首访也可能复杂；不作为本段唯一核心。
- 加热／磨刀／十点／节奏QTE：返回已被否定的认知轴或精度劳作；本段不采用。
- 同时加每三锤三选锻纹：已有有限主动技法，先验证一个选择系统，避免叠加。
- 只给收藏／未来承诺：不能证明奖励改变打法，采用固定工具尾声。

## Risks / Trade-offs

手算显示两流派能安全过主门、争匣需承担至少一记风险，仍不能证明长期均衡／真实诱惑；崩纹确定爆发、固定解谜、追工具最优路线都可能再变成机械操作。一次90秒段的目的就是暴露这个风险，不靠更多章节／遗物掩盖。参数变化须同步正式提案／核／回放，不能只改测试期望。

已有用户负评真实保留；人类是否主动换打法／为工具冒险／失败后调整与技术无重复奖励分别记录。没有提前的fun认可或规模矩阵成功声明。

## Migration Plan

批准前只有文档；具体批准后已实施独立新入口／新存储key，保旧v5和所有旧解释器／SDK／存档／原画／失败证据，隔离核查见上述必要边界复核。新开段明确确认并保取消零副作用；不读旧钱包作初始资源。共享单写／generation机制可复用，具体适配不得更改旧codec语义。默认入口切换不在本提案范围。回滚为新增revert／旧不可变预览，不删除新旧档或强推历史。

## Verification boundary

仅必要有限命令例、随机／取消／消费／奖励幂等／尾声与保存全回放、严格构建、单现代PC浏览器两流派／一次失败调整／两尺寸可见性；案例明确是新局还是合法恢复。跟随新玩法实际变化，不重跑旧384／1000种子／全音频原生矩阵。手算、规范校验、模型或mockup不能冒称实际UI／人类体验。
