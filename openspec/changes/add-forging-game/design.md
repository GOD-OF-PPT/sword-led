# 实施设计

## Context

项目为空白 PC 网页游戏，用户要求先完善设计、确认实施文档，先内核后完整 UI，主界面从三套生成稿中选择。GitHub 私有仓库已创建；当前仅文档。

## Goals / Non-Goals

- Goals：十二轮完整可玩、确定性规则、真正的回收/商人/胜负/续玩、选定风格的一致美术、可审查验证与远程交付。
- Non-Goals：本次没有账号、在线支付、多人、排行榜、移动端或低版本浏览器需求；不引入这些系统改变核心体验。

## Decisions

- TypeScript + Vite；纯规则 Module，以 createRun/applyCommand/getRunView/validateRun 组成小 Interface。
- DOM/CSS 负责可读可操作控件，Canvas 2D 负责场景；两种表现从同一视图读取，均不拥有规则。
- 双随机流、整数时机标记、pre-strike 状态计算风险；动作带 runId/revision，终结/结算/购买原子执行。
- 版本化主档/备份与 dirty 提示；Web Lock 控制同源单可写会话。正常加载不重复领域事件。
- 独立内核和模拟先实施；美术选择后才派生素材并接完整界面。

详细数据、时序、异常和目录见 [架构](../../../docs/architecture.md)，完整流程见 [UI](../../../docs/ui-design.md)，工具核实见 [依据](../../../docs/technical-sources.md)。本文件引用这些合同，不复制不同版本的公式。

## Risks / Trade-offs

- 概率可能掩盖技巧 → 公开风险、精准改善、跨种子多策略对照、真人反馈分层报告。
- 纯 DOM/Canvas 需自行管理生命周期 → 唯一会话/输入 attempt、稳定 DOM、显式 dispose、浏览器重复进入回归。
- 图稿可能好看但无法交互 → 同一实局数据、文本代码渲染、素材分层/alpha/锚点验证。
- 本地存储可能拒绝写入 → 保留内存状态、显示未保存、重试/备份/试玩出口，不假称持久化成功。

## Migration Plan

无旧业务迁移。逐任务提交，规则版本变更解释存档兼容性，保留旧数据与概念图；回滚用 revert，不强制推送。未来有部署才归档已部署规格，当前不提前把提案搬到已交付真相目录。
