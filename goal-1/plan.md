## 产品方向与决策

核心体验是“亲手敲击 + 看得懂的风险 + 见好就收”：12 轮契约，每轮三件承包铁坯，成功锻造提高价值；交货保住当轮订单，继续锻造争取更高收益；破损与回收有真实代价。商人每三轮出现，改变后续策略。惩罚使用有限契约印记，避免欠款滚雪球造成无意义拖延。

先形成明确规则和数值草案，再用确定性内核、策略模拟与真人试玩验证。数值是待验证设计，不伪称已证明“高可玩性”。美术候选比较不同氛围与空间表达，保留同一信息结构与玩法，不通过改规则制造差异。

## 风险与缓解

| 风险 | 应对与判断标准 |
| --- | --- |
| 玩法变成纯概率赌博 | 可观察的材料/热度/应力；技巧影响概率；每击显示风险；有保值交货和回收；用策略对照检验 |
| 无限重试/回收/刷新套利 | 有限三坯、加热次数、随机状态入档；所有经济变更通过内核；重复动作不重复结算 |
| 惩罚造成不可逆失败滚雪球 | 扣契约印记，不提高下一轮配额或追加负债；尽早明确失败；允许快速重开 |
| 概念图无法实现 | 同一玩法布局、可拆资产、UI 文本代码渲染；不将整张图当最终游戏界面 |
| 用户主界面选择未到 | 只推进独立内核；T07–T12 保留待办，不冒充完成、不用超时默认选择 |
| 未确认实施文档 | 完成可审阅文档与图稿后明确请求确认；不越过用户与 OpenSpec 的确认门槛 |
| 浏览器计时导致后台作弊或惩罚 | 冻结后台计时；单次击打动作锁；刷新/暂停不额外扣资源；不靠帧率驱动规则 |
| GitHub 发布失败/同名冲突 | 已核实身份；创建失败先查远程状态；不覆盖已有仓库；保留本地提交并明确故障 |
| 完美/100% 自信不可客观证明 | 按用户要求逐项自审并修复发现的问题；以验证证据闭环，诚实记录未验证条件，不伪称零缺陷 |
